# v0.6.0 完成度评估

## 1. 评估目的

本文件用于回答一个关键问题：

`v0.6.0` 到底是“能力已经完成”，还是“真实实验数据已经跑出来”。

结论先行：

- **能力层面**：基本完成，并且已归档。
- **真实数据采集层面**：当前仓库里**没有发现已落盘的实验输出数据**，因此不能把 `v0.6.0` 解释为“已经完成真实压测采集”。

## 2. 已完成的能力

以下能力已经在仓库中形成闭环，并且对应 OpenSpec / 主 spec 已同步：

- `experiment-foundation`
- `metrics-snapshot-and-recording`
- `scenario-runner-and-baseline`
- `adaptive-policy-and-control-gate`
- `offline-replay-and-readiness-gate`
- `executor-adapter-and-adjustment-evidence`
- `pressure-data-acquisition-and-baseline`

这些能力说明项目已经具备：

- 可控实验基础设施；
- 确定性场景运行能力；
- 指标采样与摘要记录能力；
- 策略评估与控制闸门；
- 离线回放和 readiness 判断；
- 受限的运行时调整证据；
- 受控的数据获取契约和报告模型。

## 3. 尚未完成的部分

尽管能力已经完成，但**真实实验数据本身并没有在仓库中被找到**。

核查结果显示：

- 仓库里没有 `outputs/` 实验输出目录；
- 没有可见的 pressure summary、replay summary、readiness summary、evidence index 或 raw evidence 文件；
- `pressure-data-acquisition-and-baseline` 的归档目录里只有文档和规范文件，没有数据产物；
- `v0.6.0` 的实验数据获取计划仍然是计划草案，不是执行结果；
- 当前状态文件也没有宣称存在一批已落盘的实验数据。

因此，`v0.6.0` 的真实定位应当是：

> **“数据采集能力已完成，但真实数据采集尚未在仓库中形成可验证的证据。”**

## 4. 为什么会出现这种情况

### 4.1 版本目标更偏向“能力边界”而不是“单次实验交付”

`v0.6.0` 的设计重点是把数据获取能力做成一个受管理边界，而不是直接保证某一批实验数据必定产生。

### 4.2 当前仓库状态已经回到无授权阶段

`docs/00-project/current-state.md` 现在是：

- `CAPABILITY_BASELINE_DELIVERED_AND_MAIN_SYNCED`
- `Current authorized work type: NONE`

这意味着当前没有活跃授权去继续跑新的实验或修改实现。

### 4.3 之前的工作主要完成的是“把流程做对”

这次工作中大量精力花在：

- schema 和门禁错配修复；
- `current-state.md` 的授权格式统一；
- `verify` / `archive` / `post-archive` 的一致性；
- 复盘与治理规则固化。

这些都很重要，但它们属于**交付治理**，不是**实验数据本身**。

## 5. 当前判断

### 结论 A：如果问“能力是否完成”

答案是：**基本完成。**

### 结论 B：如果问“真实实验数据是否已经跑出来”

答案是：**没有看到。**

### 结论 C：如果问“是否应该立刻开下一个版本”

答案是：**不应该。**

在没有真实实验数据证据之前，继续往下开新版本会把问题从“能力是否闭环”错误地变成“版本是否继续生长”。

## 6. 下一步建议

建议按下面顺序处理：

1. **先确认是否要补跑真实数据。**
   - 如果要补跑，需要单独授权一个明确的执行阶段。
   - 如果不补跑，就只能把 `v0.6.0` 视为“能力闭环、数据待采”。

2. **不要立即开启新的版本设计。**
   - 先把 `v0.6.0` 的真实数据缺口说清楚。
   - 再判断这个缺口是否需要新的授权。

3. **如果后续要做数据采集，必须先定义采集目标与落盘位置。**
   - 例如 `outputs/reports/...`
   - 以及哪些文件是必需的证据产物。

4. **如果没有真实数据需求，就停在当前闭环状态。**
   - 保持当前基线。
   - 以当前能力作为后续版本的输入。

## 7. 最终判断

`v0.6.0` 已经完成了**能力建设和治理闭环**，但没有在仓库中留下可见的**真实实验数据产物**。

所以最准确的描述是：

> `v0.6.0` 完成了“把数据采集能力做出来”，但没有证明“已经采到并保存了真实数据”。
