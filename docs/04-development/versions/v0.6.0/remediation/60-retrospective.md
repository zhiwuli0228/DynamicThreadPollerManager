# v0.6.0 补救措施包复盘

## 头信息

- 日期：`2026-06-06`
- 对象：`v0.6.0-remediation`
- 范围：补救真实数据缺口的独立设计包
- 完成状态：`design-only complete`
- 关联提交：待后续补救执行授权后补齐
- 参与 agent：Codex

## 计划路径与实际路径

| 项 | 计划 | 实际 | 偏差 |
| --- | --- | --- | --- |
| 需求/设计推进 | 不修改原始 v0.6.0 正文，单独起补救包 | 已创建独立 remediation 包 | 无 |
| 实现/验证 | 不在本轮执行实现 | 未执行实现，仅完成设计闭环 | 符合预期 |
| 归档/收尾 | 作为独立设计资产保留 | 已写入 v0.6.0 目录并索引 | 无 |

## 发生了什么

- 仓库核查后确认：`v0.6.0` 能力已完成，但没有可见的真实实验输出数据。
- 因此没有继续修改原始设计正文，而是创建了一个独立的补救设计包。
- 这个补救包完整覆盖了 IR、IR review、IR disposition、IR closure verification、SR、SR review、SR disposition、SR closure verification 和 decision log。

## 根因

### 1.

- 真实数据缺口与能力闭环被混在一起，容易误把“能力已完成”当作“数据已采集”。

### 2.

- 如果直接改写原始 `v0.6.0` 文档，后续弱 agent 可能会失去历史边界，无法区分原始设计与补救设计。

## 已采纳的改进

### 1.

- 将补救逻辑独立成 `docs/04-development/versions/v0.6.0/remediation/`。

### 2.

- 在 `v0.6.0` README 中仅添加索引，不修改原始设计正文。

## 仍然存在的问题

- 真实数据仍未在仓库中落盘。
- 补救包目前只是设计闭环，未进入执行授权。

## 后续必须遵守的行为

- 以后如果要补采真实数据，必须先通过补救包的独立流程授权。
- 在没有执行授权前，不得把设计包描述成已完成的数据采集。
- 不得修改原始 `v0.6.0` 正文来掩盖数据缺口。
