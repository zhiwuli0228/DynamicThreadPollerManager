- Package name: `v0.6.0-remediation`
- Status: `DRAFT`
- Current phase: `REMEDIATION_IR_DRAFT`
- Authoring date: `2026-06-06`
- Input baseline: `v0.6.0` original IR / SR 闭环文档、当前 state、归档 change、主 spec、仓库文件系统状态
- Current conclusion: 这是一个独立的补救设计，不是对原始设计文档的重写

## 1. 需求来源

- 用户确认项：需要补齐真实实验数据，而不是继续扩展抽象能力。
- 项目问题：当前仓库没有可见的真实输出数据文件，无法证明压测数据已经采集。
- 前置能力：`v0.6.0` 的数据采集能力和治理闭环已经完成。

## 2. 当前问题

本项目已经具备数据采集能力，但缺少真实数据产物。换句话说：

- 能力可以做数据；
- 但仓库里没有证据表明已经真正做过一轮数据采集并保留下来。

## 3. 范围

范围内：

- 定义补救性真实数据采集流程；
- 定义输出目录与文件集合；
- 定义数据质量门禁；
- 定义 evidence retention 与清理责任；
- 定义补救完成的验收条件。

范围外：

- 修改原始 `v0.6.0` 设计文档正文；
- 修改已归档 capability spec；
- 新增 queue resizing / mutation / controller；
- 新增 dependency；
- 将补救方案伪装成已有真实数据。
