## 1. 设计目标

v0.10.0 SR 将已闭环 IR 转成后续 OpenSpec change 可执行的功能设计。目标：在 v0.7.0 的 ManagedExecutor 域和 v0.9.0 的 queue resize 链路基础上，实现 rejection policy 的动态替换能力——通过 `ThreadPoolExecutor.setRejectedExecutionHandler()`（JDK 公开 API，无需 executor rebuild），并修复 `ExecutorRebuildStrategy` 硬编码 `AbortPolicy()` 的策略丢失缺陷。

本设计只描述功能边界和组件契约，不授权 Java 实现，不授权 OpenSpec change 创建。

## 2. 设计结论

- **RejectionPolicyCommand**: 不可变 record，封装目标 `RejectedExecutionHandler`，独立于 `ScaleAdjustmentCommand` 和 `QueueResizeCommand`
- **ManagedExecutor.setRejectionPolicy()**: 委托给 `TPE.setRejectedExecutionHandler()`，`getRejectionPolicy()` 直接委托给 TPE（删除独立字段，单一数据源 — 处置 IR F07，选择方案 B）
- **RejectionPolicyAdjustmentAdapter**: 新建独立 adapter，不修改现有两个 adapter
- **RejectionPolicySafetyGate**: 独立类（不实现 ControlGate），检查 executor 状态、policy 有效性、no-op、并发 resize
- **PolicyReplacementResult**: 独立 result 类型（遵循 v0.9.0 复盘流程改进 #2），不复用 AdjustmentResult 或 QueueResizeResult
- **PolicyReplacementEvidence**: record，通过 PolicyReplacementResult 携带
- **ExecutorRebuildStrategy 修复**: 一行变更：`new ThreadPoolExecutor.AbortPolicy()` → `oldTpe.getRejectedExecutionHandler()`
- 端到端测试覆盖四种 JDK 策略切换 + rebuild 策略保留 + DENY 路径
- 现有 476 测试零回归

## 4. 组件设计

### 4.1 RejectionPolicyCommand

**包**: `com.zhiwu.dynamicthreadpollermanager.experiment.executor`

**职责**: 不可变参数容器，封装 rejection policy 替换请求。

**接口契约**:

```java
// 已验证 API 签名: RejectedExecutionHandler — JDK java.util.concurrent 公开接口
// 已验证 API 签名: RejectedExecutionHandler 四种内置实现均为无状态单例

public record RejectionPolicyCommand(
        RejectedExecutionHandler targetPolicy,
        String reason) {

    public RejectionPolicyCommand {
        java.util.Objects.requireNonNull(targetPolicy, "targetPolicy must not be null");
        if (reason == null || reason.isBlank()) {
            throw new IllegalArgumentException("reason must not be blank");
        }
    }

    /**
     * 工厂方法：无变更时返回 empty。
     * 使用 class 比较——JDK 四种内置策略均为无状态单例，
     * class 比较即语义比较。自定义 handler out of scope (IR F05 处置).
     */
    public static java.util.Optional<RejectionPolicyCommand> fromCurrent(
            RejectedExecutionHandler current,
            RejectedExecutionHandler target,
            String reason) {
        java.util.Objects.requireNonNull(current, "current must not be null");
        java.util.Objects.requireNonNull(target, "target must not be null");
        if (current.getClass() == target.getClass()) {
            return java.util.Optional.empty();
        }
        return java.util.Optional.of(new RejectionPolicyCommand(target, reason));
    }
}
```

**设计决策**:
- 独立于 `ScaleAdjustmentCommand` 和 `QueueResizeCommand`——三者操作不同维度（thread / queue / policy）
- `fromCurrent()` 使用 class 比较（处置 IR F05）——JDK 四种内置策略都是无状态单例，class 比较即语义比较。自定义 handler out of scope
- 无需 `timeoutMs` 字段——`TPE.setRejectedExecutionHandler()` 是瞬时 volatile 写，不会阻塞
- 无需 `direction` 枚举——policy 替换没有 EXPAND/SHRINK 方向概念

### 4.2 ManagedExecutor 修改

**包**: `com.zhiwu.dynamicthreadpollermanager.experiment.executor`

**职责**: 添加 `setRejectionPolicy()` 方法，`getRejectionPolicy()` 改为直接委托 TPE。

**接口契约**（仅列出变更部分）:

```java
// 已验证 API 签名: ThreadPoolExecutor.setRejectedExecutionHandler(RejectedExecutionHandler)
//   — JDK 公开方法，volatile 字段，线程安全
// 已验证 API 签名: ThreadPoolExecutor.getRejectedExecutionHandler() → RejectedExecutionHandler
//   — JDK 公开方法，volatile 读

public class ManagedExecutor implements AutoCloseable {

    // 删除: private final RejectedExecutionHandler rejectionPolicy;
    // (处置 IR F07: 方案 B — 直接委托 TPE, 单一数据源)

    // 现有构造器保持不变 — rejectionHandler 参数仍传入 TPE 构造
    // 但不再存储到独立字段

    /**
     * 返回底层 TPE 的当前 RejectedExecutionHandler。
     * 直接委托给 TPE，保证始终与 TPE 内部状态一致。
     */
    public RejectedExecutionHandler getRejectionPolicy() {
        return this.executor.getRejectedExecutionHandler();  // ← 变更：直接委托 TPE
    }

    /**
     * 替换底层 TPE 的 RejectedExecutionHandler。
     * 委托给 TPE.setRejectedExecutionHandler() — 原子 volatile 写。
     */
    public void setRejectionPolicy(RejectedExecutionHandler newPolicy) {
        java.util.Objects.requireNonNull(newPolicy, "rejectionPolicy must not be null");
        this.executor.setRejectedExecutionHandler(newPolicy);
    }

    // 其余 public API 不变: submit, getCorePoolSize, setCorePoolSize, etc.
}
```

**设计决策**:
- **方案 B (直接委托)** — 处置 IR F07。删除 `rejectionPolicy` 字段，`getRejectionPolicy()` 直接从 TPE 读取
  - 单一数据源（TPE 内部的 `volatile RejectedExecutionHandler`），零不一致风险
  - 每调用读 volatile 的性能影响可忽略（policy 查询不是热路径）
  - 更简单的实现（不需要维护同步缓存）
- 现有构造器签名不变——`rejectionHandler` 参数仍传入 TPE 构造
- `toSnapshot()` 不记录 rejection policy（snapshot 关注线程/队列状态，不关注 policy 类型）——当前 snapshot 也从未包含此信息

### 4.3 RejectionPolicySafetyGate

**包**: `com.zhiwu.dynamicthreadpollermanager.experiment.policy`

**职责**: 在 policy 替换前评估安全性。

**接口契约**:

```java
// 已验证 API 签名: ManagedExecutor.isShutdown() → boolean
// 已验证 API 签名: ManagedExecutor.isTerminated() → boolean
// 已验证 API 签名: ManagedExecutor.getRejectionPolicy() → RejectedExecutionHandler
// 已验证 API 签名: QueueResizeSafetyGate.evaluate() 签名: (QueueResizeCommand, ManagedExecutor) → EvaluationResult
//   — RejectionPolicySafetyGate 遵循相同独立接口模式

public final class RejectionPolicySafetyGate {

    public enum GateResult { PERMIT, DENY }

    public record EvaluationResult(GateResult result, String reason) {
        public boolean permitted() {
            return result == GateResult.PERMIT;
        }
    }

    private final java.util.function.Predicate<String> isResizeInProgress;

    /**
     * @param isResizeInProgress 注入函数，检查指定 executorId 是否正在 resize。
     *                          实际由 QueueResizeAdjustmentAdapter.isResizeInProgress() 提供。
     *                          (处置 IR F02: 函数式注入，解耦 safety gate 与 adapter)
     */
    public RejectionPolicySafetyGate(
            java.util.function.Predicate<String> isResizeInProgress) {
        this.isResizeInProgress = java.util.Objects.requireNonNull(
                isResizeInProgress, "isResizeInProgress must not be null");
    }

    /**
     * 评估 rejection policy 替换的安全性。
     *
     * @param command  目标 policy 替换命令
     * @param executor 目标 managed executor
     * @param executorId 用于并发 resize 检查
     */
    public EvaluationResult evaluate(
            RejectionPolicyCommand command,
            ManagedExecutor executor,
            String executorId) {

        // Check 1: Executor running
        // 已验证: ManagedExecutor.isShutdown() / isTerminated() 返回 boolean
        if (executor.isShutdown() || executor.isTerminated()) {
            return new EvaluationResult(GateResult.DENY,
                    "executor is not in RUNNING state");
        }

        // Check 2: Policy not null (二次确认; command 构造时已验证)
        if (command.targetPolicy() == null) {
            return new EvaluationResult(GateResult.DENY,
                    "target policy must not be null");
        }

        // Check 3: No-op detection (class 比较)
        // 已验证: ManagedExecutor.getRejectionPolicy() 返回 RejectedExecutionHandler
        RejectedExecutionHandler currentPolicy = executor.getRejectionPolicy();
        if (command.targetPolicy().getClass() == currentPolicy.getClass()) {
            return new EvaluationResult(GateResult.DENY,
                    "target policy is same type as current policy (no-op)");
        }

        // Check 4: Concurrent resize protection (处置 IR F02)
        // 已验证: 注入的 Predicate<String> 由 QueueResizeAdjustmentAdapter.isResizeInProgress() 提供
        if (isResizeInProgress.test(executorId)) {
            return new EvaluationResult(GateResult.DENY,
                    "executor is currently undergoing queue resize");
        }

        return new EvaluationResult(GateResult.PERMIT, "policy replacement permitted");
    }
}
```

**设计决策**:
- **独立接口**（不实现 `ControlGate<T>`）— 遵循 v0.9.0 复盘流程改进 #3 "ControlGate 接口的适用边界"。Policy safety gate 不需要 `ExecutorStateSnapshot` 或 `ReadinessSummary` 参数，模式与 `QueueResizeSafetyGate` 相同
- **`Predicate<String>` 注入**（处置 IR F02）— `RejectionPolicySafetyGate` 不直接依赖 `QueueResizeAdjustmentAdapter`。通过函数式接口注入 `isResizeInProgress` 检查，保持 safety gate 与 adapter 的解耦。实际注入 `queueResizeAdapter::isResizeInProgress` 方法引用
- **No-op 检测使用 class 比较**— 与 `RejectionPolicyCommand.fromCurrent()` 保持一致
- **不检查 queue 深度**— policy 替换不涉及任务排空或丢失，无需 queue 深度检查

### 4.4 RejectionPolicyAdjustmentAdapter

**包**: `com.zhiwu.dynamicthreadpollermanager.experiment.executor`

**职责**: 接收 RejectionPolicyCommand，经过 safety gate 评估后调用 ManagedExecutor.setRejectionPolicy()。

**接口契约**:

```java
// 已验证 API 签名: ExecutorRegistry.get(String) → Optional<ManagedExecutor>
// 已验证 API 签名: ManagedExecutor.setRejectionPolicy(RejectedExecutionHandler)
// 已验证 API 签名: ManagedExecutor.getRejectionPolicy() → RejectedExecutionHandler
// 已验证 API 签名: ManagedExecutor.toSnapshot() → ExecutorStateSnapshot
// 已验证 API 签名: QueueResizeResult 静态工厂:
//   success(ResizeEvidence) / failed(String, String) / failed(String, String, ResizeEvidence)
// 已验证 API 签名: QueueResizeAdjustmentAdapter 构造:
//   (ExecutorRegistry, QueueResizeSafetyGate, ExecutorRebuildStrategy)

public final class RejectionPolicyAdjustmentAdapter {

    private final ExecutorRegistry registry;
    private final RejectionPolicySafetyGate safetyGate;

    public RejectionPolicyAdjustmentAdapter(
            ExecutorRegistry registry,
            RejectionPolicySafetyGate safetyGate) {
        this.registry = java.util.Objects.requireNonNull(registry,
                "registry must not be null");
        this.safetyGate = java.util.Objects.requireNonNull(safetyGate,
                "safetyGate must not be null");
    }

    /**
     * 执行 rejection policy 替换。
     *
     * @param executorId 目标 executor 注册 ID
     * @param command    策略替换命令
     * @return PolicyReplacementResult — 独立 result 类型
     *         (遵循 v0.9.0 复盘流程改进 #2: 每个 adapter 返回专用 result 类型)
     */
    public PolicyReplacementResult apply(
            String executorId,
            RejectionPolicyCommand command) {

        java.util.Objects.requireNonNull(executorId, "executorId must not be null");
        java.util.Objects.requireNonNull(command, "command must not be null");

        // 1. 查找 executor
        java.util.Optional<ManagedExecutor> found = registry.get(executorId);
        if (found.isEmpty()) {
            return PolicyReplacementResult.failed(
                    "EXECUTOR_NOT_FOUND",
                    "no executor with id " + executorId);
        }

        ManagedExecutor executor = found.get();

        // 2. 读取 before policy (用于 evidence)
        RejectedExecutionHandler beforePolicy = executor.getRejectionPolicy();
        java.time.Instant startTime = java.time.Instant.now();

        // 3. Safety gate 评估
        RejectionPolicySafetyGate.EvaluationResult gateResult =
                safetyGate.evaluate(command, executor, executorId);

        if (gateResult.result() == RejectionPolicySafetyGate.GateResult.DENY) {
            PolicyReplacementEvidence evidence = new PolicyReplacementEvidence(
                    beforePolicy.getClass().getCanonicalName(),
                    beforePolicy.getClass().getCanonicalName(), // after == before (未替换)
                    executor.toSnapshot(),
                    startTime,
                    false,
                    gateResult.reason());
            return PolicyReplacementResult.denied(
                    "SAFETY_GATE_DENIED",
                    gateResult.reason(),
                    evidence);
        }

        // 4. 执行替换
        try {
            executor.setRejectionPolicy(command.targetPolicy());
        } catch (RuntimeException ex) {
            PolicyReplacementEvidence evidence = new PolicyReplacementEvidence(
                    beforePolicy.getClass().getCanonicalName(),
                    beforePolicy.getClass().getCanonicalName(),
                    executor.toSnapshot(),
                    startTime,
                    false,
                    "setRejectionPolicy failed: " + ex.getMessage());
            return PolicyReplacementResult.failed(
                    "POLICY_SET_FAILED",
                    ex.getMessage(),
                    evidence);
        }

        // 5. 构建 success evidence
        PolicyReplacementEvidence evidence = new PolicyReplacementEvidence(
                beforePolicy.getClass().getCanonicalName(),
                command.targetPolicy().getClass().getCanonicalName(),
                executor.toSnapshot(),
                startTime,
                true,
                command.reason());

        return PolicyReplacementResult.success(evidence);
    }
}
```

**设计决策**:
- **新建独立 adapter**— 遵循 IR F02 处置。不修改 `ManagedExecutorAdjustmentAdapter` 或 `QueueResizeAdjustmentAdapter`
- **无需幂等保护**（IR F03 处置）— policy-policy 并发: last-write-wins（`TPE.setRejectedExecutionHandler()` 是原子 volatile 写）。与 `QueueResizeAdjustmentAdapter` 不同——policy 替换不涉及 executor 重建，不存在中间状态
- **无需 ExecutorRebuildStrategy 依赖**— 与 `QueueResizeAdjustmentAdapter` 的关键差异：policy 替换是直接 setter 操作，不经过 rebuild
- **`apply()` 流程**: find → read before → safety gate → set → build result。与现有两个 adapter 的流程模式一致

### 4.5 PolicyReplacementResult

**包**: `com.zhiwu.dynamicthreadpollermanager.experiment.executor`

**职责**: `RejectionPolicyAdjustmentAdapter` 的专用返回类型。

**接口契约**:

```java
// 已验证 API 签名: QueueResizeResult 静态工厂模式:
//   success(ResizeEvidence) / failed(String, String) / failed(String, String, ResizeEvidence)
// PolicyReplacementResult 遵循相同模式 (处置 IR F01: 新增独立 result 类型)

public final class PolicyReplacementResult {

    private final boolean success;
    private final PolicyReplacementEvidence evidence;
    private final String failureCode;
    private final String reason;

    private PolicyReplacementResult(boolean success,
                                     PolicyReplacementEvidence evidence,
                                     String failureCode,
                                     String reason) {
        this.success = success;
        this.evidence = evidence;
        this.failureCode = failureCode;
        this.reason = reason;
    }

    public static PolicyReplacementResult success(PolicyReplacementEvidence evidence) {
        java.util.Objects.requireNonNull(evidence, "evidence must not be null");
        return new PolicyReplacementResult(true, evidence, null, null);
    }

    public static PolicyReplacementResult denied(String failureCode, String reason,
                                                   PolicyReplacementEvidence evidence) {
        java.util.Objects.requireNonNull(failureCode, "failureCode must not be null");
        java.util.Objects.requireNonNull(evidence, "evidence must not be null");
        return new PolicyReplacementResult(false, evidence, failureCode, reason);
    }

    public static PolicyReplacementResult failed(String failureCode, String reason) {
        java.util.Objects.requireNonNull(failureCode, "failureCode must not be null");
        return new PolicyReplacementResult(false, null, failureCode, reason);
    }

    public static PolicyReplacementResult failed(String failureCode, String reason,
                                                   PolicyReplacementEvidence evidence) {
        java.util.Objects.requireNonNull(failureCode, "failureCode must not be null");
        return new PolicyReplacementResult(false, evidence, failureCode, reason);
    }

    public boolean success() { return success; }
    public PolicyReplacementEvidence evidence() { return evidence; }
    public String failureCode() { return failureCode; }
    public String reason() { return reason; }
}
```

**设计决策**:
- **独立 result 类型**（处置 IR F01）— 遵循 v0.9.0 复盘流程改进 #2 "独立 result 类型模式"
- 三个 result 类型各自独立:
  - `AdjustmentResult` → `ScaleAdjustmentCommand` (v0.7.0)
  - `QueueResizeResult` → `QueueResizeCommand` (v0.9.0)
  - `PolicyReplacementResult` → `RejectionPolicyCommand` (v0.10.0)
- `denied()` 工厂方法 — 与 `failed()` 区分（DENIED 意味着 safety gate 拦截，不是系统错误），携带 evidence
- `failed()` 两个重载: 无 evidence（查询阶段失败，如 EXECUTOR_NOT_FOUND）和有 evidence（执行阶段失败，如 POLICY_SET_FAILED）

### 4.6 PolicyReplacementEvidence

**包**: `com.zhiwu.dynamicthreadpollermanager.experiment.executor`

**职责**: 记录 policy 替换操作的标准化证据。

**接口契约**:

```java
// 已验证 API 签名: ExecutorStateSnapshot — 现有 record，通过 toSnapshot() 获取
// 已验证 API 签名: ResizeEvidence 模式:
//   record ResizeEvidence(boolean success, ExecutorStateSnapshot beforeState,
//       ExecutorStateSnapshot afterState, long rebuildDurationMs, int drainedTaskCount,
//       int rejectedTaskCount, String direction, int oldQueueCapacity,
//       int newQueueCapacity, String errorMessage)

public record PolicyReplacementEvidence(
        String beforePolicyClass,       // 旧 policy 的 canonical class name
        String afterPolicyClass,        // 新 policy 的 canonical class name
        ExecutorStateSnapshot executorState,  // 替换时刻的 executor 状态
        java.time.Instant replacedAt,   // 替换时间戳
        boolean success,                // 替换是否成功
        String reason                   // 替换原因或失败原因
) {}
```

**设计决策**:
- **独立 evidence 类型**— 与 `ResizeEvidence` 模式相同但字段更少（policy 替换不需要 before/after 双快照，也不需要 drainedCount/rejectedCount 等 rebuild 相关字段）
- `executorState` 是替换时刻的 executor 状态快照（非 before/after 双快照）——policy 替换是瞬时操作，一次快照足够
- `beforePolicyClass`/`afterPolicyClass` 使用 canonical class name（String），避免持有 `RejectedExecutionHandler` 引用（防止 evidence 持有 policy 实例的生命周期问题）
- DENIED 时 `afterPolicyClass == beforePolicyClass`（替换未实际发生）

```java
//   — private final ConcurrentHashMap<String, Boolean>

/**
 * 检查指定 executor 是否正在执行 queue resize。
 * 供 RejectionPolicySafetyGate 使用 — 防止 policy 替换与 resize 并发。
 * (处置 IR F02)
 */
public boolean isResizeInProgress(String executorId) {
    return resizeInProgress.containsKey(executorId);
}
```

**设计决策**:
- 公开已有内部状态，通过简单方法
- 线程安全——`ConcurrentHashMap.containsKey()` 是原子操作
- 最小侵入——不改变 `resizeInProgress` 的访问级别（保持 private），只新增一个公开的查询方法
