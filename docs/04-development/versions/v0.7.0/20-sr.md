## 1. 设计目标

`v0.7.0` SR 将已闭环 IR 转成后续 OpenSpec change 可执行的功能设计。目标是将 v0.1.0-v0.6.0 构建的实验基础设施首次桥接到真实 `java.util.concurrent.ThreadPoolExecutor`，完成一次受控闭环实验，同时保持所有现有安全边界不变。

本设计只描述功能边界和组件契约，不授权 Java 实现，不授权 OpenSpec change 创建。

## 2. 设计结论

- `ManagedExecutor` 直接包装 `ThreadPoolExecutor`，不引入中间调度层或自定义线程管理。
- `ExecutorRegistry` 使用 `ConcurrentHashMap` 单进程实现，不涉及外部存储或分布式协调。
- 调整路径复用 v0.5.0 的 `ExecutorAdjustmentAdapter` 契约和 `RuntimeAdjustmentSafetyGate`：“安全门先行，调整后行”。
- `InMemoryAdjustableExecutorProbe` 保留不删，与新 adapter 通过 DI/工厂共存。
- 闭环实验使用 `ScenarioProfile.STEADY`；策略决策路径可复现，timing-dependent 状态值允许波动。
- 不引入 queue resizing、闭环调度、持久化、REST/API/UI、外部依赖。
- `ExecutorStateSnapshot` 通过扩展字段兼容真实 `ThreadPoolExecutor` 状态，不创建并行快照类。

## 4. 组件设计

### 4.1 ManagedExecutor

**包**: `com.zhiwu.dynamicthreadpollermanager.experiment.executor`

**职责**: 包装 `ThreadPoolExecutor`，提供安全可控的参数调整和状态读取。

**接口契约**:

```java
public class ManagedExecutor implements AutoCloseable {

    // 构造
    public ManagedExecutor(int corePoolSize, int maxPoolSize, long keepAliveTime,
                           TimeUnit unit, BlockingQueue<Runnable> workQueue);
    public ManagedExecutor(int corePoolSize, int maxPoolSize, long keepAliveTime,
                           TimeUnit unit, BlockingQueue<Runnable> workQueue,
                           ThreadFactory threadFactory, RejectedExecutionHandler rejectionHandler);

    // 任务提交
    public <T> Future<T> submit(Callable<T> task);
    public Future<?> submit(Runnable task);

    // 可调整参数 getter/setter（委托给底层 ThreadPoolExecutor）
    public int getCorePoolSize();
    public void setCorePoolSize(int corePoolSize);
    public int getMaximumPoolSize();
    public void setMaximumPoolSize(int maximumPoolSize);
    public long getKeepAliveTime(TimeUnit unit);
    public void setKeepAliveTime(long time, TimeUnit unit);

    // 只读状态（从 ThreadPoolExecutor 实时读取）
    public int getActiveCount();
    public int getPoolSize();
    public int getQueueSize();
    public long getCompletedTaskCount();
    public int getLargestPoolSize();
    public long getTaskCount();

    // 只读配置（构造时设定，不可变）
    public int getQueueCapacity();
    public RejectedExecutionHandler getRejectionPolicy();

    // 生命周期
    public void shutdown();
    public List<Runnable> shutdownNow();
    public boolean isShutdown();
    public boolean isStopped();
    public boolean isTerminated();
    public boolean awaitTermination(long timeout, TimeUnit unit) throws InterruptedException;

    // 逃生舱口
    public ThreadPoolExecutor unwrap();

    // AutoCloseable → shutdown()
    @Override public void close() { shutdown(); }
}
```

**构造参数默认值**: threadFactory 默认 `Executors.defaultThreadFactory()`，rejectionHandler 默认 `new ThreadPoolExecutor.AbortPolicy()`。

**设计决策**:
- `setCorePoolSize` / `setMaximumPoolSize` 直接委托，不作额外校验（校验由安全门负责）。
- `getQueueSize()` 返回 `getQueue().size()`，O(1) 操作（`LinkedBlockingQueue` 内部维护计数）。
- `getQueueCapacity()` 返回 `queue.remainingCapacity() + queue.size()`。
- `unwrap()` 返回底层 `ThreadPoolExecutor`，供后续扩展使用，但不暴露为公开 API 的主要路径。

### 4.2 ExecutorRegistry

**包**: `com.zhiwu.dynamicthreadpollermanager.experiment.executor`

**职责**: 管理 `ManagedExecutor` 实例的命名注册、查找和受保护删除。

**接口契约**:

```java
public class ExecutorRegistry {
    public void register(String name, ManagedExecutor executor);
    public Optional<ManagedExecutor> get(String name);
    public List<String> list();           // unmodifiable snapshot
    public boolean remove(String name);   // returns false if blocked by DeletionSafety
    public int size();
}
```

**线程安全**: 使用 `ConcurrentHashMap<String, ManagedExecutor>` 支撑所有操作。

**删除规则**:
- `remove(name)` 不自动 shutdown 执行器。调用者负责：先 `shutdown()` → `awaitTermination()` → `remove()`。
- `DeletionSafety.canRemove()` 返回 `false` 时，`remove()` 返回 `false`，不删除。

### 4.3 RuntimeSetting

**包**: `com.zhiwu.dynamicthreadpollermanager.experiment.executor`

**职责**: 枚举可调整/不可调整参数，定义安全边界。

```java
public enum AdjustableParameter {
    CORE_POOL_SIZE,
    MAX_POOL_SIZE,
    KEEP_ALIVE_TIME
}

public enum NonAdjustableParameter {
    QUEUE_CAPACITY,
    REJECTION_POLICY
}

public final class IntParameterBounds {
    private final int minValue;
    private final int maxValue;
    public static IntParameterBounds of(int minValue, int maxValue);
    public boolean within(int value);     // minValue <= value <= maxValue
}

public final class LongParameterBounds {
    private final long minValue;
    private final long maxValue;
    public static LongParameterBounds of(long minValue, long maxValue);
    public boolean within(long value);
}

public final class RuntimeSetting {
    public static final IntParameterBounds CORE_POOL_SIZE_BOUNDS = IntParameterBounds.of(1, Integer.MAX_VALUE);
    public static final IntParameterBounds MAX_POOL_SIZE_BOUNDS = IntParameterBounds.of(1, Integer.MAX_VALUE);
    public static final LongParameterBounds KEEP_ALIVE_TIME_BOUNDS = LongParameterBounds.of(0, Long.MAX_VALUE);
    // 运行时额外约束：maxPoolSize >= corePoolSize
}
```

**安全边界默认值**: `corePoolSize >= 1`, `maxPoolSize >= corePoolSize`, `keepAliveTime >= 0`。

### 4.4 DeletionSafety

**包**: `com.zhiwu.dynamicthreadpollermanager.experiment.executor`

**职责**: 基于原子引用计数的删除安全判断。

**接口契约**:

```java
public interface DeletionSafety {
    void acquire(String executorName);
    void release(String executorName);
    int referenceCount(String executorName);
    boolean canRemove(String executorName, ExecutorRegistry registry);
}

public class AtomicDeletionSafety implements DeletionSafety {
    // uses ConcurrentHashMap<String, AtomicInteger>
}
```

**规则**:
- `canRemove(name, registry)` 返回 `true` 当且仅当：引用计数 == 0 且 `registry.get(name).isTerminated() == true`（修正 F02）。
- `acquire()` / `release()` 使用 `AtomicInteger`，线程安全（修正 F07）。
- 引用计数不得为负数：`release()` 在计数为 0 时抛 `IllegalStateException`。

### 4.5 ManagedExecutorAdjustmentAdapter

**包**: `com.zhiwu.dynamicthreadpollermanager.experiment.executor`

**职责**: 实现 `ExecutorAdjustmentAdapter`，将调整命令桥接到真实 `ManagedExecutor`。

**接口实现**:

```java
public class ManagedExecutorAdjustmentAdapter implements ExecutorAdjustmentAdapter {

    private final ExecutorRegistry registry;
    private final RuntimeAdjustmentSafetyGate safetyGate;
    private final String executorName;

    public ManagedExecutorAdjustmentAdapter(
            ExecutorRegistry registry,
            RuntimeAdjustmentSafetyGate safetyGate,
            String executorName) { ... }

    @Override
    public ExecutorStateSnapshot currentState() {
        ManagedExecutor executor = registry.get(executorName)
                .orElseThrow(() -> new IllegalStateException(
                        "executor not found: " + executorName));
        return executor.toSnapshot();
    }

    @Override
    public AdjustmentResult apply(ScaleAdjustmentCommand command) {
        // 1. 从 registry 获取目标 ManagedExecutor
        // 2. 采集 beforeState = ExecutorStateSnapshot
        // 3. 调用 safetyGate.check(command, beforeState)
        // 4. 若 REJECTED → 返回 AdjustmentResult(REJECTED, beforeState, reason)
        // 5. 调用 managedExecutor.setCorePoolSize(cmd.targetCorePoolSize())
        //        managedExecutor.setMaximumPoolSize(cmd.targetMaxPoolSize())
        // 6. 采集 afterState = ExecutorStateSnapshot
        // 7. 若成功 → 返回 AdjustmentResult(APPLIED, beforeState, afterState)
        // 8. 若异常 → 返回 AdjustmentResult(FAILED, beforeState, failureCode)
    }
}
```

**调整流程**:

```text
ScaleAdjustmentCommand
    │
    ├── 1. registry.get(targetName) → ManagedExecutor
    ├── 2. beforeState = collectSnapshot(executor)
    ├── 3. decision = safetyGate.check(command, beforeState)
    │       └── REJECTED → return AdjustmentResult(REJECTED, beforeState, reason)
    ├── 4. executor.setCorePoolSize(command.targetCorePoolSize())
    │       executor.setMaximumPoolSize(command.targetMaxPoolSize())
    │       └── RuntimeException → return AdjustmentResult(FAILED, beforeState, failureCode)
    ├── 5. afterState = collectSnapshot(executor)
    └── 6. return AdjustmentResult(APPLIED, beforeState, afterState)
```

**与 InMemoryAdjustableExecutorProbe 共存**: 通过 Spring `@Qualifier("managedExecutor")` / `@Qualifier("probe")` 区分。闭环实验使用 `managedExecutor`；现有单元测试继续使用 `probe`。

### 4.6 ExecutorStateSnapshot 扩展

**现有字段**（v0.5.0，保留不变）: `observedAt`, `corePoolSize`, `maximumPoolSize`, `activeCount`, `queueSize`, `queueCapacity`

**新增字段**（v0.7.0，nullable 以保证向后兼容）:

| 字段 | 类型 | 来源 | 确定性 | 说明 |
| --- | --- | --- | --- | --- |
| `poolSize` | `Integer` | `getPoolSize()` | OBSERVATIONAL | 当前线程数，延迟创建 |
| `completedTaskCount` | `Long` | `getCompletedTaskCount()` | OBSERVATIONAL | 已完成任务数 |
| `keepAliveTimeSeconds` | `Long` | `getKeepAliveTime(SECONDS)` | DETERMINISTIC | 保活时间，setter 后立即可见 |
| `largestPoolSize` | `Integer` | `getLargestPoolSize()` | OBSERVATIONAL | 历史最大线程数 |
| `taskCount` | `Long` | `getTaskCount()` | OBSERVATIONAL | 总任务数（含执行中+已完成） |

**兼容策略**: 所有新字段使用 `null` 默认值。`Builder` 新增对应 setter。现有代码未设置这些字段时，`getXxx()` 返回 `null`（保持二进制兼容）。`equals()` / `hashCode()` 包含新字段。

**采集方法**（`ManagedExecutor` 上）:

```java
public ExecutorStateSnapshot toSnapshot() {
    return ExecutorStateSnapshot.builder(Instant.now())
            .corePoolSize(getCorePoolSize())
            .maximumPoolSize(getMaximumPoolSize())
            .activeCount(getActiveCount())
            .poolSize(getPoolSize())
            .queueSize(getQueueSize())
            .queueCapacity(getQueueCapacity())
            .completedTaskCount(getCompletedTaskCount())
            .keepAliveTimeSeconds(getKeepAliveTime(TimeUnit.SECONDS))
            .largestPoolSize(getLargestPoolSize())
            .taskCount(getTaskCount())
            .build();
}
```

### 4.7 安全门集成

不创建新的安全门。调整路径直接使用 v0.5.0 的：

| 安全门 | 使用位置 | 输入 |
| --- | --- | --- |
| `RuntimeAdjustmentSafetyGate.check()` | `ManagedExecutorAdjustmentAdapter.apply()` 第 3 步 | `ScaleAdjustmentCommand` + `ExecutorStateSnapshot`（beforeState） |
| `MutationReadinessGate` | 闭环实验前，评估是否允许对该执行器进行调整 | `ExecutorStateSnapshot` 序列 + readiness thresholds |

`SafetyGateConfig` 通过构造注入 `ManagedExecutorAdjustmentAdapter`，不硬编码。

## 5. 状态与失败语义

### 5.1 AdjustmentStatus（复用 v0.5.0）

| 状态 | 触发条件 |
| --- | --- |
| `APPLIED` | 安全门通过，`setCorePoolSize`/`setMaximumPoolSize` 成功 |
| `REJECTED` | 安全门返回 `REJECTED` 或参数越界 |
| `FAILED` | 安全门通过但底层 `ThreadPoolExecutor` 抛出异常 |
| `NO_OP` | `command.targetPoolSize() == currentState.poolSize()` |

### 5.2 AdjustmentFailureCode（复用 v0.5.0，增补 1 项）

增补：`EXECUTOR_NOT_FOUND` — registry 中未找到目标执行器。

### 5.3 DeletionSafety 失败语义

| 场景 | 结果 |
| --- | --- |
| `refCount > 0` | `canRemove()` → `false`, `remove()` → `false` |
| `isTerminated() == false` | `canRemove()` → `false`, `remove()` → `false` |
| `refCount == 0 && isTerminated()` | `canRemove()` → `true`, `remove()` → `true` |
| `release()` 时 `refCount == 0` | 抛出 `IllegalStateException` |

### 5.4 ManagedExecutor 生命周期状态机

```text
RUNNING ──shutdown()──→ SHUTDOWN ──tasks complete──→ TERMINATED
   │                        │
   │                        └──shutdownNow()──→ STOP (interrupt)
   │
   └──submit() 正常接收任务
       SHUTDOWN/STOP/TERMINATED 状态下 submit() → RejectedExecutionException
```

## 7. 并发、资源、观测边界

### 7.1 并发安全

| 组件 | 并发策略 |
| --- | --- |
| `ManagedExecutor` | 底层 `ThreadPoolExecutor` 自身线程安全；getter 为瞬时快照，不保证原子跨字段 |
| `ExecutorRegistry` | `ConcurrentHashMap` 保证单个操作原子性；`register`/`remove` 间有 check-then-act 窗口（可接受，实验场景非高频） |
| `DeletionSafety` | `AtomicInteger` + `ConcurrentHashMap` 保证计数原子性 |
| `ManagedExecutorAdjustmentAdapter` | `apply()` 同步调用安全门和 setter，单次调整原子 |

### 7.2 资源管理

| 资源 | 管理策略 |
| --- | --- |
| 线程 | `ManagedExecutor` shutdown 释放核心线程；`awaitTermination` 超时后强制 `shutdownNow()` |
| 队列 | 构造时指定，shutdown 后队列内剩余任务不执行 |
| Registry 内存 | `remove()` 后从 `ConcurrentHashMap` 移除，GC 回收（前提：调用方已 shutdown） |

### 7.3 观测边界

- `ManagedExecutor` 状态通过 `toSnapshot()` 暴露，不直接暴露 `ThreadPoolExecutor` 引用（`unwrap()` 除外）。
- 快照采集是瞬时读取，不保证多次调用间的一致性。
- 指标管道集成（IR F06 deferred）：`ExecutorStateSnapshot` 可作为 `ObservedSnapshot` 的扩展数据源；SR 建议 `PressureSampler` 通过 adapter 获取快照，而非直接访问 `ManagedExecutor`。

## 8. 闭环实验设计

### 8.1 实验场景

```
Scenario: Steady workload 闭环实验

Given:
  - ManagedExecutor(core=2, max=4, keepAlive=60s, queue=LinkedBlockingQueue(10))
  - ScenarioDefinition(profile=STEADY, seed=42, stepCount=20, baseWorkUnits=100)
  - ThresholdPolicyConfig(label="default", ...)
  - RuntimeAdjustmentSafetyGate(cooldown=2, maxAdjustments=5)
  - 执行器已注册到 ExecutorRegistry("experiment-executor")

When:
  1. 运行场景，采集 pressure snapshots (pre-adjustment, 10 steps)
  2. 策略评估产出 ScaleDecision(targetPoolSize=6, reason="queue pressure")
  3. 安全门检查通过
  4. ManagedExecutorAdjustmentAdapter.apply(command)
  5. 继续运行场景 (post-adjustment, 10 steps)
  6. 采集调整后 snapshots

Then:
  - AdjustmentResult.status == APPLIED
  - beforeState.corePoolSize == 2, afterState.corePoolSize == 6 (参数变更可验证)
  - post-adjustment poolSize 在 [2, 6] 范围内（允许线程延迟创建）
  - 实验产出: runManifest, pressureSummary, adjustmentEvidence
```

### 8.2 可复现性边界

- 相同输入（scenario definition + seed + policy config + baseline preset）→ 相同 `ScaleDecision` 和调整参数。
- `activeCount`、`poolSize`、`queueSize` 时序值允许因线程调度在 ±50% 范围内波动。
- 实验报告必须记录 JDK 版本、OS、CPU 核心数。

## 9. 与现有组件的集成映射（IR deferred items 回应）

| IR deferred | SR 设计决策 |
| --- | --- |
| F03: 采集时序 | `ManagedExecutorAdjustmentAdapter.apply()` 中 beforeState 在安全门前采集，afterState 在 setter 调用后立即采集。参数变更是即时的（setter 调用完成即可见），但 `poolSize` 反映的线程数可能延迟。闭环验收以参数变更（corePoolSize setter 前后的值）为判定依据，不以 `poolSize` 瞬时值为判定依据。 |
| F05: BaselineWorkloadExecutor 集成 | `ManagedExecutor` **不**实现 `BaselineWorkloadExecutor` 接口。闭环实验的执行路径：在端到端测试类中直接编排调用序列，不依赖 `ScenarioExperimentRunner`。编排顺序：(1) 创建 `ManagedExecutor` 并注册；(2) 通过 `ManagedExecutor.submit()` 提交 scenario tasks；(3) 通过 `ManagedExecutorAdjustmentAdapter.currentState()` 采集快照；(4) 通过 `PressureSampler` / `ThresholdPolicyEvaluator` 产出 `ScaleDecision`；(5) 通过 adapter 执行调整；(6) 采集调整后快照并比对。`BaselineWorkloadExecutor` 和 `ScenarioExperimentRunner` 不做任何修改。 |
| F06: metrics 管道集成 | `ExecutorStateSnapshot` 扩展字段与 `ObservedSnapshot` 有重叠（`activeCount`, `queueSize` 两方都有）。SR 建议 `SnapshotAssembler` 新增 `fromExecutorState(ExecutorStateSnapshot)` 工厂方法，将 `ExecutorStateSnapshot` 转为 `ObservedSnapshot` 输入。具体实现留给 OpenSpec change 阶段。 |

## 10. 测试与验收策略

### 10.2 测试要求

- 核心执行路径必须使用真实 `ThreadPoolExecutor`，不可 mock。
- 并发测试必须遵循 `docs/04-development/testing-guide.md` 的确定性并发测试规则。
- 每个测试 `@AfterEach` 或 `@AfterAll` 必须 shutdown 测试中创建的 `ManagedExecutor`。

### 10.3 非回归约束

- `mvn test` 全量通过。
- `InMemoryAdjustableExecutorProbe` 的现有测试不经修改即可通过。
