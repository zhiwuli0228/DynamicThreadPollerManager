# v0.7.0 IR 需求分析草案

## Header

- Document type: IR requirement draft
- Version name: `v0.7.0`
- Status: `DRAFT`
- Current phase: `MANAGED_EXECUTOR_DOMAIN_REQUIREMENT_DRAFT`
- Authoring date: `2026-06-11`
- Current conclusion: 本文只定义 managed executor domain 需求，不授权 SR、OpenSpec change、Java 实现

## 1. 需求来源

### 1.1 用户确认方向

用户要求从项目整体蓝图出发，起草 v0.7.0 版本设计。经 `00-objectives-and-scope.md` 和 `decision-log.md` 基线确认后，进入 IR 需求分析阶段。方向明确：将实验基础设施桥接到真实 `ThreadPoolExecutor`，完成首次闭环实验。

### 1.2 项目现状

v0.1.0 到 v0.6.0 已交付六层能力，但全部运行在 `InMemoryAdjustableExecutorProbe`（内存探针）之上：

| 已交付能力 | 与真实执行器的关系 | 当前限制 |
| --- | --- | --- |
| `scenario-runner-and-baseline` | 使用 `BaselineWorkloadExecutor`，底层是探针 | 任务不会被真实线程执行 |
| `metrics-snapshot-and-recording` | 从探针读取模拟状态 | 没有真实的 active/pool/queue 数据 |
| `adaptive-policy-and-control-gate` | 基于探针数据评估策略 | 策略从未驱动过真实调整 |
| `offline-replay-and-readiness-gate` | 回放模拟调整序列 | readiness 结论针对不存在的问题 |
| `executor-adapter-and-adjustment-evidence` | `ScaleAdjustmentCommand` 只作用于探针 | 调整后无真实行为变化 |
| `pressure-data-acquisition-and-baseline` | 采集探针的模拟压力数据 | 数据质量和分类结果缺乏物理意义 |

当前结构性缺口：

- **没有受管理的真实执行器**：所有实验证据来自探针，无法证明策略在真实线程调度下的行为。
- **调整命令没有真实落点**：`ScaleAdjustmentCommand` 设计完整，参数校验到位，但 `setCorePoolSize` / `setMaximumPoolSize` 从未被调用。
- **安全门的保护对象不存在**：`MutationReadinessGate`、`RuntimeAdjustmentSafetyGate`、`ReadinessClassifier` 都就绪了，但没有真实的危险操作需要它们保护。
- **架构文档的目标模型未实现**：`managed-executor-domain-model.md` 描述的 `ManagedExecutor`、`ExecutorRegistry`、`RuntimeSetting`、`DeletionSafety` 全部是纸面设计。

### 1.3 需求判断

此时引入真实 `ThreadPoolExecutor` 接管是合理的下一步，理由：

- v0.5.0 的安全门（`RuntimeAdjustmentSafetyGate`、`MutationReadinessGate`）已闭环，可以在调整前提供真实防护。
- v0.6.0 的数据质量门禁和 readiness 判定已闭环，可以作为调整前置条件套用到真实执行器上。
- 架构文档 `managed-executor-domain-model.md` 为 `ManagedExecutor` 提供了稳定的目标模型。
- `InMemoryAdjustableExecutorProbe` 的接口（`ExecutorAdjustmentAdapter`）已经是现成的桥接契约。
- 不做 queue resizing、不做闭环调度、不进生产 — 风险可控，只做受控实验。

## 2. 范围

### 2.1 范围内

- `ManagedExecutor` 抽象，直接包装 `java.util.concurrent.ThreadPoolExecutor`。
- `ExecutorRegistry` 命名注册表，支持创建、查找、列举和删除安全检查。
- `RuntimeSetting` 模型，明确可调整参数与不可调整参数。
- `DeletionSafety` 规则，基于引用计数的删除安全判断。
- `ExecutorAdjustmentAdapter` 的真实 `ThreadPoolExecutor` 实现。
- `ExecutorStateSnapshot` 从真实 `ThreadPoolExecutor` 采集状态。
- 首次闭环实验：steady workload → metrics → policy → adjustment → post-observation。
- 现有 `MutationReadinessGate` 和 `SafetyGate` 在真实调整前的集成。
- 所有现有测试继续通过（无回归）。

### 2.2 范围外

- Queue resizing（`ThreadPoolExecutor` 的 work queue 运行时替换）。
- 生产 `ThreadPoolExecutor` 集成或线上环境。
- 闭环调度器/控制器（自动连续运行）。
- 持久化、数据库、文件存储。
- REST / API / UI。
- 外部依赖引入。
- Rejection policy 运行时切换。
- 多执行器协调、分布式场景。
- Throughput improvement claim。
- Virtual threads、ForkJoinPool 等其他执行器类型。

### 2.3 术语

| 术语 | 定义 |
| --- | --- |
| ManagedExecutor | 包装 `ThreadPoolExecutor` 的安全抽象，暴露可控参数和只读状态 |
| ExecutorRegistry | 进程内命名注册表，管理 `ManagedExecutor` 实例的生命周期 |
| RuntimeSetting | 明确定义哪些执行器参数可在运行时调整，哪些不可 |
| DeletionSafety | 基于引用计数的删除安全检查，防止移除正在使用的执行器 |
| Adjustment bridge | `ScaleAdjustmentCommand` 到 `ThreadPoolExecutor.setCorePoolSize()`/`setMaximumPoolSize()` 的连接通道 |
| State bridge | `ExecutorStateSnapshot` 从真实 `ThreadPoolExecutor` 采集状态的通道 |
| Closed-loop experiment | scenario → metrics → policy → adjustment → post-observation 完整链路 |
| Safety gate integration | 真实调整前必须通过 `RuntimeAdjustmentSafetyGate` 和 `MutationReadinessGate` 检查 |
| InMemoryAdjustableExecutorProbe | v0.5.0 引入的内存探针，v0.7.0 后降级为测试辅助，不再充当主要调整目标 |

## 3. IR 条目草案

### IR-v0.7-001 ManagedExecutor 抽象

系统需要 `ManagedExecutor` 包装 `ThreadPoolExecutor`，提供安全、可控的参数调整接口和只读状态暴露。

候选验收语义：

- `ManagedExecutor` 必须接受构造参数：core pool size、max pool size、keep-alive time、time unit、work queue（`BlockingQueue<Runnable>`）、thread factory（可选）、rejection policy（可选）。
- 必须暴露可调整参数：`getCorePoolSize()`、`setCorePoolSize(int)`、`getMaximumPoolSize()`、`setMaximumPoolSize(int)`、`getKeepAliveTime()`、`setKeepAliveTime(long, TimeUnit)`，且 setter 调用直接委托给底层 `ThreadPoolExecutor`。
- 必须暴露只读状态：`getActiveCount()`、`getPoolSize()`、`getQueueSize()`、`getCompletedTaskCount()`、`getLargestPoolSize()`、`getTaskCount()`。
- 必须暴露只读配置：`getQueueCapacity()`、`getRejectionPolicy()` — 创建时设定，运行时不可变。
- `submit(Callable<T>)` 和 `submit(Runnable)` 必须委托给底层 `ThreadPoolExecutor`。
- 所有方法必须线程安全（底层 `ThreadPoolExecutor` 已提供）。
- 不得在 `ManagedExecutor` 中新增 queue resizing 或 rejection policy 切换逻辑。
- 必须提供 `shutdown()` 方法，委托给底层 `ThreadPoolExecutor.shutdown()`，发起有序关闭。
- 必须提供 `isShutdown()` 和 `isTerminated()` 查询方法。
- 必须提供 `awaitTermination(long timeout, TimeUnit)` 方法。
- 实验或测试结束时，持有方负责调用 `shutdown()` 并等待终止。

优先级：P0。

### IR-v0.7-002 ExecutorRegistry 注册表

系统需要 `ExecutorRegistry` 命名注册表，管理 `ManagedExecutor` 实例的生命周期。

候选验收语义：

- 必须支持 `register(name, ManagedExecutor)` 操作，name 不可为空，不可重复注册。
- 必须支持 `get(name)` 返回 `Optional<ManagedExecutor>`。
- 必须支持 `list()` 返回不可修改的 name 列表或 snapshot。
- 必须支持 `remove(name)` 操作，且删除前必须通过 `DeletionSafety` 检查。
- 必须支持 `size()` 返回当前注册表条目数。
- 所有操作必须线程安全（推荐 `ConcurrentHashMap` 支持）。
- 不得支持跨进程注册或外部存储。
- `remove(name)` 不自动 shutdown 执行器。调用者必须确保执行器已终止（`isTerminated() == true`）后再调用 `remove()`。
- `DeletionSafety.canRemove(name)` 必须额外检查：若执行器未终止（`isTerminated() == false`），返回 `false` 并记录未终止原因。

优先级：P0。

### IR-v0.7-003 RuntimeSetting 模型与调整边界

系统需要明确定义哪些执行器参数可在运行时调整，哪些不可。

候选验收语义：

- 可调整参数枚举必须包含：`CORE_POOL_SIZE`、`MAX_POOL_SIZE`、`KEEP_ALIVE_TIME`。
- 不可调整参数枚举必须包含：`QUEUE_CAPACITY`、`REJECTION_POLICY`。
- `RuntimeSetting` 必须为每个可调整参数定义安全边界：`minValue`、`maxValue`、`stepConstraint`（如有）。
- 安全边界默认值：`corePoolSize >= 1`、`maxPoolSize >= corePoolSize`、`keepAliveTime >= 0`。
- 违反安全边界的调整请求必须被拒绝，并记录违反原因。
- 不得在 `RuntimeSetting` 中新增不属于标准 `ThreadPoolExecutor` 的虚构参数。

优先级：P0。

### IR-v0.7-004 DeletionSafety 删除安全

系统需要防止在 `ManagedExecutor` 仍被活跃实验引用时从注册表中删除。

候选验收语义：

- `DeletionSafety` 必须提供 `canRemove(name, registry)` 判断接口。
- 默认实现必须使用引用计数语义：执行器被 `ExperimentCoordinator` 或 `ScenarioExperimentRunner` 持有时 `acquire()`，释放时 `release()`。
- `canRemove(name)` 返回 `false` 当且仅当引用计数 > 0。
- 引用计数必须使用原子操作（`AtomicInteger` 或等效机制），`acquire()` / `release()` 必须线程安全，引用计数不得为负数。
- 不得使用外部锁或分布式协调实现删除安全。

优先级：P1。

### IR-v0.7-005 调整命令桥接

系统需要将 `ScaleAdjustmentCommand` 连接到真实 `ThreadPoolExecutor` 的参数调整方法。

候选验收语义：

- 必须实现 `ExecutorAdjustmentAdapter` 接口的真实执行器版本（`ManagedExecutorAdjustmentAdapter`）。
- `apply(cmd)` 方法必须：1) 从 `ExecutorRegistry` 获取目标 `ManagedExecutor`；2) 运行 `RuntimeAdjustmentSafetyGate.check()`；3) 通过后调用 `setCorePoolSize(cmd.targetCorePoolSize())` 和 `setMaximumPoolSize(cmd.targetMaxPoolSize())`；4) 返回 `AdjustmentResult` 含成功/失败状态和调整前后快照。
- `SafetyGateDecision.REJECTED` 时不得调用 `setCorePoolSize` 或 `setMaximumPoolSize`。
- 调整后必须立即采集 `ExecutorStateSnapshot` 作为 `AdjustmentResult.postState()`。
- 调整失败（如参数越界）必须返回 `AdjustmentStatus.FAILED` 并携带 `AdjustmentFailureCode`。
- 不得绕过安全门直接调整。

优先级：P0。

### IR-v0.7-006 状态采集桥接

系统需要从真实 `ThreadPoolExecutor` 采集 `ExecutorStateSnapshot`。

候选验收语义：

- 必须实现从 `ManagedExecutor` 采集状态快照的方法。
- 快照字段：`activeCount`（来自 `getActiveCount()`）、`poolSize`（来自 `getPoolSize()`）、`queueSize`（来自 `getQueue().size()`）、`completedTaskCount`（来自 `getCompletedTaskCount()`）、`corePoolSize`、`maxPoolSize`、`keepAliveTime`、`timestamp`。
- 快照采集必须是某一时刻的原子读取（同一方法调用中读取所有字段）。
- 快照不得包含虚构或推算值 — 所有值必须直接来自 `ThreadPoolExecutor`。
- 必须与现有 `ExecutorStateSnapshot` 的字段语义兼容。

优先级：P0。

### IR-v0.7-007 安全门集成

系统需要在真实调整路径中集成 v0.5.0 的 `RuntimeAdjustmentSafetyGate` 和 `MutationReadinessGate`。

候选验收语义：

- 每次 `ScaleAdjustmentCommand` 执行前，必须调用 `RuntimeAdjustmentSafetyGate.check(command, currentState)`。
- `MutationReadinessGate` 评估必须基于真实采集的 `ExecutorStateSnapshot`（不再是探针数据）。
- 安全门拒绝时，调整链路必须终止，返回 `REJECTED` 状态的 `AdjustmentResult`。
- 安全门配置（`SafetyGateConfig`）必须允许设置 max step size、min/max pool size bounds。
- 不得在安全门未通过时静默执行调整。

优先级：P0。

### IR-v0.7-008 闭环实验验证

系统需要运行首次完整的闭环实验，证明 scenario → metrics → policy → adjustment → post-observation 链路在真实 `ThreadPoolExecutor` 上可工作。

候选验收语义：

- 实验必须使用 `ScenarioProfile.STEADY`（固定速率）场景。
- 实验必须：1) 部署 `ManagedExecutor` + 场景；2) 运行场景采集 pressure snapshots；3) 策略评估产生 `ScaleDecision`；4) 通过安全门后执行调整；5) 继续运行，采集调整后 snapshots；6) 比较调整前后状态差异。
- 调整前后 `poolSize` 必须有可验证的变化（core pool size 从 N 调整为 M，M != N）。
- 实验输出必须包含 run manifest、pressure summary、adjustment evidence。
- 实验的策略决策路径必须可复现：相同 scenario / policy config / baseline preset → 相同 `ScaleDecision` 和调整参数。timing-dependent 的运行时状态值（`activeCount`、`poolSize`、`queueSize` 时序）允许因线程调度在合理范围内波动，不作为严格复现判定依据。
- 不得声称实验结果代表生产环境性能。

优先级：P0。

### IR-v0.7-009 非回归与测试覆盖

系统需要保证所有现有测试继续通过，且新增代码有对应测试覆盖。

候选验收语义：

- `mvn test` 必须全量通过，包含所有已有测试和新增测试。
- 新增测试必须覆盖：`ManagedExecutor` 生命周期（构造、submit、shutdown）、`ExecutorRegistry` CRUD 和并发安全、`DeletionSafety` 引用计数、`ManagedExecutorAdjustmentAdapter` 调整成功/拒绝/越界路径、`ExecutorStateSnapshot` 采集精度、闭环实验端到端。
- 测试必须使用真实 `ThreadPoolExecutor`（不可使用 mock 替代核心执行路径）。
- 并发测试必须遵循 `docs/04-development/testing-guide.md` 的确定性并发测试规则。

优先级：P0。

### IR-v0.7-010 探针降级

v0.5.0 的 `InMemoryAdjustableExecutorProbe` 在 v0.7.0 后降级为测试辅助角色。

候选验收语义：

- `InMemoryAdjustableExecutorProbe` 不得被删除，保留用于调整路径的单元测试。
- 新的 `ManagedExecutorAdjustmentAdapter` 成为实验运行中的主要调整目标。
- `ExecutorAdjustmentAdapter` 接口保持不变，两个实现共存：`InMemoryAdjustableExecutorProbe`（测试用）、`ManagedExecutorAdjustmentAdapter`（实验用）。
- 现有使用探针的测试不得因新增真实实现而失败。

优先级：P1。

## 6. 风险和延期项

| 风险 | 当前判断 | 后续触发条件 |
| --- | --- | --- |
| `ThreadPoolExecutor` 线程调度不确定性影响实验可复现性 | P1 风险 | SR 必须确认 deterministic time bounds 或固定 seed 策略 |
| 闭环实验中策略评估阈值依赖探针数据标定，迁移到真实执行器后阈值可能失效 | P1 风险 | SR 必须定义阈值校准策略 |
| `ManagedExecutor` 包装可能过度限制 `ThreadPoolExecutor` 原生能力 | P2 风险 | 预留 `unwrap()` 方法供后续扩展 |
| `DeletionSafety` 引用计数实现可能不覆盖所有引用路径 | P1 风险 | SR 必须穷举所有引用入口 |
| 闭环实验运行期间 JVM 状态波动影响 post-adjustment 测量 | P2 风险 | 实验报告记录 JVM 环境信息 |
| v0.5.0/v0.6.0 接口语义与真实 `ThreadPoolExecutor` 行为不兼容 | P1 风险 | SR 必须逐接口对比，记录兼容/不兼容决策 |
| 把闭环实验的一次性结果误读为策略有效性证明 | P0 风险 | 文档必须明确禁止 throughput/performance improvement claim |

- 安全门集成是否复用而非重写 v0.5.0 安全抽象。
- 探针降级是否保留而非删除现有能力。
- 闭环实验的成功标准是否可验证、不越界。
- 是否能给弱实现 agent 足够具体的 SR 输入。

## 8. IR 阶段出口条件

进入 SR 前必须完成：

1. `11-ir-review.md` — 独立 IR review findings。
2. `12-ir-review-disposition.md` — 逐项处置 findings。
3. `13-ir-closure-verification.md` — 独立验证 P0/P1 已关闭。
4. 更新 `docs/00-project/current-state.md`，明确是否允许进入 `v0.7.0` SR 功能设计。
5. 不得在 IR closure 前创建 OpenSpec change、Java 实现或闭环实验执行任务。

## 9. 当前结论

`v0.7.0` IR 草案已定义 managed executor domain 的需求方向：10 条 IR 覆盖 `ManagedExecutor` 抽象、`ExecutorRegistry` 注册表、`RuntimeSetting` 模型、`DeletionSafety`、调整桥接、状态桥接、安全门集成、闭环实验验证、非回归测试和探针降级。本文不授权实现、实验执行或 OpenSpec change；下一步是独立 IR review。
