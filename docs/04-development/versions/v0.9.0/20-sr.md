## 1. 设计目标

v0.9.0 SR 将已闭环 IR 转成后续 OpenSpec change 可执行的功能设计。目标：在 v0.7.0 的 ManagedExecutor 域和 v0.8.0 的数据获取管道基础上，实现 queue capacity 的动态调整能力——通过 ExecutorRebuildStrategy（decommission → commission 周期）解决 ThreadPoolExecutor 不支持运行时 queue 替换的限制。

本设计只描述功能边界和组件契约，不授权 Java 实现，不授权 OpenSpec change 创建。

## 2. 设计结论

- **QueueResizeCommand**: 不可变 record，封装 target queue capacity，独立于 ScaleAdjustmentCommand（操作不同维度）
- **ExecutorRebuildStrategy**: decommission 流程 = `stopAccepting → shutdown → drainTo → awaitTermination`；commission = `new ThreadPoolExecutor(resizedQueue) → wrap ManagedExecutor → re-register`（处置 F05 race condition）
- **QueueResizeSafetyGate**: 实现 ControlGate 接口，检查容量合法性、SHRINK 安全性（queue depth ≤ new capacity）、executor RUNNING 状态、幂等保护
- **QueueResizeAdjustmentAdapter**: 新建独立 adapter，不修改 ManagedExecutorAdjustmentAdapter（处置 F02）
- **ResizeEvidence**: 通过 AdjustmentResult 携带，不经过 EvidenceRecorder（处置 F04）
- 端到端测试覆盖 EXPAND + SHRINK + SAFETY_GATE_DENY 三条路径
- 现有 433 测试零回归

## 4. 组件设计

### 4.1 QueueResizeCommand

**包**: `com.zhiwu.dynamicthreadpollermanager.experiment.executor`

**职责**: 不可变参数容器，封装 queue capacity 调整请求。

**接口契约**:

```java
public record QueueResizeCommand(
    int targetQueueCapacity,
    String resizeReason,
    long timeoutMs
) {
    public QueueResizeCommand {
        if (targetQueueCapacity <= 0)
            throw new IllegalArgumentException(
                "targetQueueCapacity must be > 0, got " + targetQueueCapacity);
        if (timeoutMs < 0)
            throw new IllegalArgumentException(
                "timeoutMs must be >= 0, got " + timeoutMs);
        // resizeReason 可为 null
    }

    // timeoutMs 默认值
    public QueueResizeCommand(int targetQueueCapacity, String resizeReason) {
        this(targetQueueCapacity, resizeReason, 30_000L);
    }

    // 工厂：无变更时返回 empty
    public static Optional<QueueResizeCommand> fromCurrent(
            int currentCapacity, int newCapacity, String reason) {
        if (newCapacity == currentCapacity) return Optional.empty();
        return Optional.of(new QueueResizeCommand(newCapacity, reason));
    }

    public enum Direction { EXPAND, SHRINK, NO_CHANGE }

    public Direction direction(int currentCapacity) {
        if (targetQueueCapacity > currentCapacity) return Direction.EXPAND;
        if (targetQueueCapacity < currentCapacity) return Direction.SHRINK;
        return Direction.NO_CHANGE;
    }
}
```

**设计决策**:
- 独立于 `ScaleAdjustmentCommand`——操作不同维度（queue vs thread），不需要共享基类
- `fromCurrent()` 返回 `Optional.empty()` 而非抛异常——无变更时的语义是"无需操作"而非"错误"
- `timeoutMs` 默认 30 秒（rebuild 比 scale 耗时更长，涉及 shutdown + awaitTermination + create）
- `resizeReason` 可选，用于日志/evidence 中的可读说明

### 4.2 ExecutorRebuildStrategy

**包**: `com.zhiwu.dynamicthreadpollermanager.experiment.executor`

**职责**: 实现安全的 executor decommission → commission 周期。

**接口契约**:

```java
public final class ExecutorRebuildStrategy {

    private final ExecutorRegistry registry;
    private final Supplier<Instant> clock;

    public ExecutorRebuildStrategy(ExecutorRegistry registry,
                                    Supplier<Instant> clock) {
        this.registry = Objects.requireNonNull(registry);
        this.clock = Objects.requireNonNull(clock);
    }

    public RebuildResult rebuild(
            String executorId,
            ManagedExecutor oldExecutor,
            QueueResizeCommand command) {

        Instant startTime = clock.get();

        // --- Snapshot before state ---
        ExecutorStateSnapshot beforeState = oldExecutor.toSnapshot();
        int oldQueueCapacity = oldExecutor.getQueueCapacity();
        int currentCorePoolSize = beforeState.corePoolSize();
        int currentMaxPoolSize = beforeState.maximumPoolSize();
        long currentKeepAliveMs = beforeState.keepAliveTimeMs();

        // --- Decommission ---
        // Step 1: Stop accepting new tasks
        // (shutdown 拒绝新提交，但不中断已在 queue 中的任务)
        oldExecutor.shutdown();

        // Step 2: Drain pending tasks from queue
        List<Runnable> drainedTasks = new ArrayList<>();
        oldExecutor.getQueue().drainTo(drainedTasks);

        // Step 3: Await termination (already shutdown)
        boolean terminated = false;
        try {
            terminated = oldExecutor.awaitTermination(
                    command.timeoutMs(), TimeUnit.MILLISECONDS);
        } catch (InterruptedException e) {
            Thread.currentThread().interrupt();
        }
        if (!terminated) {
            oldExecutor.shutdownNow();
            // Best-effort: force termination
            try {
                terminated = oldExecutor.awaitTermination(5, TimeUnit.SECONDS);
            } catch (InterruptedException e) {
                Thread.currentThread().interrupt();
            }
        }

        // --- Commission ---
        // Step 4: Create new ThreadPoolExecutor with resized queue
        ThreadPoolExecutor newTpe;
        try {
            newTpe = new ThreadPoolExecutor(
                currentCorePoolSize,
                currentMaxPoolSize,
                currentKeepAliveMs, TimeUnit.MILLISECONDS,
                new LinkedBlockingQueue<>(command.targetQueueCapacity()),
                oldExecutor.getThreadFactory(),
                new ThreadPoolExecutor.AbortPolicy()
            );
        } catch (Exception e) {
            // Commission failed — old executor already shut down
            // Cannot recover old executor; return failure
            Instant endTime = clock.get();
            return new RebuildResult(
                false, beforeState, null,
                Duration.between(startTime, endTime).toMillis(),
                drainedTasks.size(),
                drainedTasks.size(), // all drained tasks lost
                command.direction(oldQueueCapacity),
                oldQueueCapacity,
                command.targetQueueCapacity(),
                "Commission failed: " + e.getMessage()
            );
        }

        ManagedExecutor newExecutor = new ManagedExecutor(newTpe);

        // Step 5: Re-register — keep same executorId (处置 F03)
        // Remove old reference, register new
        registry.remove(executorId);
        registry.register(executorId, newExecutor);

        // --- Replay drained tasks (if any) ---
        int replayedCount = 0;
        int rejectedCount = 0;
        if (!drainedTasks.isEmpty()
                && command.direction(oldQueueCapacity) == QueueResizeCommand.Direction.EXPAND) {
            for (Runnable task : drainedTasks) {
                try {
                    newExecutor.submit(task);
                    replayedCount++;
                } catch (RejectedExecutionException e) {
                    rejectedCount++;
                }
            }
        }
        // SHRINK: drained tasks 不 replay（drain-and-discard）；
        // 若 SR 决定需要 replay，SR 阶段评估 F08

        // --- Snapshot after state ---
        ExecutorStateSnapshot afterState = newExecutor.toSnapshot();

        Instant endTime = clock.get();
        return new RebuildResult(
            true,
            beforeState,
            afterState,
            Duration.between(startTime, endTime).toMillis(),
            drainedTasks.size(),
            rejectedCount,
            command.direction(oldQueueCapacity),
            oldQueueCapacity,
            command.targetQueueCapacity(),
            null // no error
        );
    }
}
```

**设计决策**:
- **Decommission 顺序**（处置 F05）: `shutdown → drainTo → awaitTermination`。shutdown 在 drain 之前调用，确保 drain 和 shutdown 之间没有新任务入队
- **Commission 失败处理**: 旧 executor 已 shutdown，无法恢复。返回 failure result + 旧 executor 状态，调用方感知
- **SHRINK drain-and-discard**（处置 F08 推荐方向）: SHRINK 时 drained 任务不 replay——新 queue 更小，replay 失败率高；旧任务丢弃、调用方在 evidence 中看到 `drainedTaskCount`
- **EXPAND drain-and-replay**: EXPAND 时 replay 到新 queue（新 queue 更大，replay 成功率高）
- **Timeout 保护**: awaitTermination 使用 `command.timeoutMs()`，超时后 shutdownNow 强制终止
- **保持同一 executorId**（处置 F03）: rebuild 的语义是"同一逻辑 executor 的配置变更"

### 4.3 QueueResizeSafetyGate

**包**: `com.zhiwu.dynamicthreadpollermanager.experiment.policy`

**职责**: 在 resize 前评估安全性。

**接口契约**:

```java
public final class QueueResizeSafetyGate
        implements ControlGate<QueueResizeCommand> {

    @Override
    public SafetyGateResult evaluate(
            QueueResizeCommand command,
            ExecutorStateSnapshot currentState,
            ReadinessSummary readiness) {
        // readiness 参数不使用（resize safety gate 不依赖 readiness）

        // Check 1: Executor running
        if (currentState.isTerminated() || currentState.isShutdown()) {
            return SafetyGateResult.deny(
                "executor is not in RUNNING state");
        }

        // Check 2: Capacity change (no-op guard)
        int currentQueueCapacity = currentState.queueCapacity();
        if (command.targetQueueCapacity() == currentQueueCapacity) {
            return SafetyGateResult.deny(
                "target queue capacity equals current capacity");
        }

        // Check 3: SHRINK safety
        if (command.targetQueueCapacity() < currentQueueCapacity) {
            int currentQueueDepth = currentState.queueSize() != null
                    ? currentState.queueSize() : 0;
            if (currentQueueDepth > command.targetQueueCapacity()) {
                return SafetyGateResult.deny(
                    "current queue depth (" + currentQueueDepth
                    + ") exceeds target capacity ("
                    + command.targetQueueCapacity() + ")");
            }
        }

        // All checks passed
        return SafetyGateResult.permit();
    }
}
```

**设计决策**:
- 实现 `ControlGate<QueueResizeCommand>` 接口保持与 `RuntimeAdjustmentSafetyGate` 相同的模式
- SHRINK 检查: queue depth > new capacity → DENY（防止数据丢失）
- 不检查 resize 方向为 EXPAND 的上限——扩容没有安全性风险
- `readiness` 参数不使用（queue resize safety 不依赖 readiness 评估）
- 幂等保护: 留在 adapter 层处理（adapter 可以检查 registry 中的 resize-in-progress 标记）

### 4.4 QueueResizeAdjustmentAdapter

**包**: `com.zhiwu.dynamicthreadpollermanager.experiment.executor`

**职责**: 接收 QueueResizeCommand，经过 safety gate 评估后执行 rebuild。

**接口契约**:

```java
public final class QueueResizeAdjustmentAdapter {

    private final ExecutorRegistry registry;
    private final QueueResizeSafetyGate safetyGate;
    private final ExecutorRebuildStrategy rebuildStrategy;

    public QueueResizeAdjustmentAdapter(
            ExecutorRegistry registry,
            QueueResizeSafetyGate safetyGate,
            ExecutorRebuildStrategy rebuildStrategy) {
        this.registry = Objects.requireNonNull(registry);
        this.safetyGate = Objects.requireNonNull(safetyGate);
        this.rebuildStrategy = Objects.requireNonNull(rebuildStrategy);
    }

    public AdjustmentResult apply(
            String executorId, QueueResizeCommand command) {

        // 1. Find executor
        ManagedExecutor executor = registry.get(executorId);
        if (executor == null) {
            return AdjustmentResult.failed(
                "EXECUTOR_NOT_FOUND",
                "no executor with id " + executorId,
                null);
        }

        // 2. Read current state for safety gate
        ExecutorStateSnapshot currentState = executor.toSnapshot();

        // 3. Safety gate evaluation
        SafetyGateResult gateResult = safetyGate.evaluate(
                command, currentState, null);

        if (!gateResult.permitted()) {
            return AdjustmentResult.failed(
                "SAFETY_GATE_DENIED",
                gateResult.reason(),
                null);
        }

        // 4. Execute rebuild
        RebuildResult rebuildResult = rebuildStrategy.rebuild(
                executorId, executor, command);

        // 5. Build adjustment result with resize evidence
        ResizeEvidence evidence = ResizeEvidence.from(rebuildResult);
        AdjustmentResult result = rebuildResult.success()
                ? AdjustmentResult.success(executorId, evidence)
                : AdjustmentResult.failed(
                    "REBUILD_FAILED",
                    rebuildResult.errorMessage(),
                    evidence);

        return result;
    }
}
```

**设计决策**:
- 新建独立 adapter，不修改 `ManagedExecutorAdjustmentAdapter`（处置 F02）
- 两个 adapter 共享 `ExecutorRegistry` 依赖但不冲突——各自操作不同 command 类型
- `apply()` 流程: find → snapshot → safety gate → rebuild → build result——与 `ManagedExecutorAdjustmentAdapter.apply(ScaleAdjustmentCommand)` 的流程模式一致
- `EXECUTOR_NOT_FOUND` 复用现有 `AdjustmentFailureCode`

### 4.5 ResizeEvidence

**包**: `com.zhiwu.dynamicthreadpollermanager.experiment.executor`

**职责**: 记录 resize 操作的完整证据。

**接口契约**:

```java
public record ResizeEvidence(
    boolean success,
    ExecutorStateSnapshot beforeState,
    ExecutorStateSnapshot afterState,    // null on failure
    long rebuildDurationMs,
    int drainedTaskCount,
    int rejectedTaskCount,
    String direction,                    // "EXPAND" / "SHRINK"
    int oldQueueCapacity,
    int newQueueCapacity,
    String errorMessage                  // null on success
) {
    public static ResizeEvidence from(RebuildResult result) {
        return new ResizeEvidence(
            result.success(),
            result.beforeState(),
            result.afterState(),
            result.rebuildDurationMs(),
            result.drainedTaskCount(),
            result.rejectedTaskCount(),
            result.direction().name(),
            result.oldQueueCapacity(),
            result.newQueueCapacity(),
            result.errorMessage()
        );
    }
}
```

**设计决策**:
- `ResizeEvidence` 通过 `AdjustmentResult.evidence()` 携带，不经过 `EvidenceRecorder`（处置 F04）
- 与 `AdjustmentResult` 的现有 `evidence()` 泛型模式一致（`AdjustmentResult<T>` 携带 `T evidence`）
- `afterState` 在 failure 时为 null——调用方可以区分部分完成的 rebuild
- 所有计数字段为 int——queue 深度和任务数不会超出 int 范围

## 5. Change Decomposition

SR 闭环后，建议的 OpenSpec change 候选：

### 候选 1: `queue-resize-command-and-rebuild`

**范围**:
- `QueueResizeCommand` record + 单元测试
- `ExecutorRebuildStrategy` + 集成测试
- `QueueResizeAdjustmentAdapter` + 集成测试
- `RebuildResult` 辅助类型
- `ResizeEvidence` record + 单元测试
- `QueueResizeSafetyGate` + 单元测试

**非范围**: 端到端 post-resize 数据获取

### 候选 2: `queue-resize-end-to-end-verification`

**范围**:
- `QueueResizeEndToEndTest`（EXPAND + SHRINK + DENY 全路径）
- Resize 后 re-run ManagedExecutorScenarioRunner 验证
- Resize evidence 完整性验证
- 全流程不变测试（433 tests zero regression）

**非范围**: command/rebuild/adapter 实现（change 1 已完成）

### 分解依赖关系

```text
queue-resize-command-and-rebuild (change 1/2)
    └── queue-resize-end-to-end-verification (change 2/2)
```

**说明**: 2 个 change 串行交付。Change 1 实现核心 resize 能力（command + rebuild + safety gate + adapter + evidence），change 2 做端到端验证和 post-resize 数据获取。2 个 change 的粒度平衡——change 1 覆盖命令→安全→执行→证据的完整链路，change 2 做集成验证闭环。
