## 1. 设计目标

v0.13.0 SR 将已闭环 IR 转成后续 OpenSpec change 可执行的功能设计。目标：在 v0.12.0 的 NormalizedComparisonMetrics 模式和 v0.4.0 的 ThresholdPolicyEvaluator 基础设施上，实现压力状态分类引擎（`PressureState` + `PressureClassifier` + `NormalizedPressureMetrics`）、策略评分与排序（`PolicyScore` + `PolicyScorer` + `PolicyRanker`）、以及 CPU 利用率数据源（`SystemCpuProbe` + `RuntimeObservation` 集成）。

关键架构约束：所有新分类和评分组件位于新包 `experiment.classification`。CPU probe 位于新包 `experiment.probe`。`RuntimeObservation.fromExecutor()` 添加重载方法（向后兼容）。

本设计只描述功能边界和组件契约，不授权 Java 实现，不授权 OpenSpec change 创建。

### 关键架构裁决

**Why new package `experiment.classification`**: 压力分类和策略评分是一个新的诊断层——它与 policy（做决策）和 scenario（做比较）正交。放入新包避免在已有的 8 个包之间引入不必要的耦合。分类器只消费 snapshots（metrics 包），不修改它们。

**Why new package `experiment.probe`**: CPU probe 是数据源，独立于分类/策略/执行器。它只依赖 JDK 标准 API。`RuntimeObservation` 可选地消费它。未来可能新增其他 probe（如 memory probe），独立包便于扩展。

**Why NormalizedPressureMetrics independent from NormalizedComparisonMetrics**: 两者服务于不同用例（分类器输入 vs 比较报告），工厂方法签名不同（`fromSnapshots()` 需要 `trendWindowSize`），字段集合不同（11 vs 9）。在类型系统中保持独立避免耦合。

**Why ThresholdPolicyScorer is rule-based**: 与 decision-log D4 一致——规则式评分可解释、零运行时开销、透明。未来版本（v0.15.0+）可在有实际运行反馈数据后改用历史性能评分。

## 4. 组件设计

### 4.1 PressureState

**包**: `com.zhiwu.dynamicthreadpollermanager.experiment.classification`

**职责**: 定义 6 个语义化压力状态标签，含优先级序和可读描述。

```java
public enum PressureState {
    REJECTION_ACTIVE("任务正被拒绝——最近窗口内检测到拒绝事件"),
    OVERLOAD("线程饱和，队列深度高——系统处于过载状态"),
    QUEUE_BUILDUP("队列持续增长中，线程尚未完全饱和——前兆状态"),
    RECOVERY("队列和线程均在下降——系统从高压力状态恢复中"),
    UNDER_UTILIZED("线程空闲，队列为空——资源利用不足"),
    NORMAL("平衡状态——线程工作中，队列在可管理范围内");

    private final String description;

    PressureState(String description) {
        this.description = description;
    }

    public String description() {
        return description;
    }
}
```

设计决策：
- enum 声明顺序即为分类优先级（从高到低）：REJECTION_ACTIVE > OVERLOAD > QUEUE_BUILDUP > RECOVERY > UNDER_UTILIZED > NORMAL
- 每个枚举值携带中文描述（`description()`），用于分类 evidence 和报告
- 枚举值顺序保证 `Enum.compareTo()` 可直接用于优先级比较：`state1.ordinal() < state2.ordinal()` 表示 state1 优先级更高

### 4.2 ClassifierConfig

**包**: `com.zhiwu.dynamicthreadpollermanager.experiment.classification`

**职责**: 分类器配置参数，含 F03 fix 新增的 queueCapacity。

```java
public record ClassifierConfig(
        int trendWindowSize,        // 趋势计算窗口（快照数），必须 >= 2
        double queueGrowthThreshold, // 队列增长率阈值（/快照），默认 0.1
        int rejectionWindowSize,    // 拒绝检测窗口（快照数），必须 >= 1
        int queueCapacity           // F03 fix: 队列容量，默认 Integer.MAX_VALUE
) {
    public ClassifierConfig {
        if (trendWindowSize < 2) {
            throw new IllegalArgumentException(
                    "trendWindowSize must be >= 2, was " + trendWindowSize);
        }
        if (queueGrowthThreshold <= 0) {
            throw new IllegalArgumentException(
                    "queueGrowthThreshold must be > 0, was " + queueGrowthThreshold);
        }
        if (rejectionWindowSize < 1) {
            throw new IllegalArgumentException(
                    "rejectionWindowSize must be >= 1, was " + rejectionWindowSize);
        }
        if (queueCapacity < 0 && queueCapacity != Integer.MAX_VALUE) {
            throw new IllegalArgumentException(
                    "queueCapacity must be >= 0 or Integer.MAX_VALUE, was " + queueCapacity);
        }
    }

    public static ClassifierConfig defaults() {
        return new ClassifierConfig(5, 0.1, 10, Integer.MAX_VALUE);
    }
}
```

设计决策：
- `queueCapacity` 默认 `Integer.MAX_VALUE`（无界队列）——当无界时，OVERLOAD 条件退化为仅检查 threadUtilizationRatio
- `trendWindowSize >= 2`：至少需要 2 个快照才能计算趋势
- `queueGrowthThreshold = 0.1`：每快照 10% 的队列增长被视为"增长中"

### 4.3 NormalizedPressureMetrics

**包**: `com.zhiwu.dynamicthreadpollermanager.experiment.classification`

**职责**: 从快照列表计算 11 个归一化压力指标。

```java
// 已验证 API 签名:
//   PressureSnapshot.activeThreads() → int, poolSize() → int, queueSize() → int,
//     completedTaskCount() → long
//   ObservedSnapshot.snapshot() → PressureSnapshot
//   ObservedSnapshot.observation() → RuntimeObservation

public record NormalizedPressureMetrics(
        long completedTaskCount,
        long rejectedTaskCount,
        double avgQueueDepth,
        int maxQueueDepth,
        long totalDurationMs,
        double throughputPerSecond,
        double avgActiveThreads,
        int maxPoolSize,
        int snapshotCount,
        double queueGrowthRate,         // 派生信号
        double threadUtilizationRatio   // 派生信号
) {
    public static NormalizedPressureMetrics fromSnapshots(
            List<ObservedSnapshot> snapshots,
            long totalDurationMs,
            int fallbackPoolSize,
            int trendWindowSize) {

        Objects.requireNonNull(snapshots, "snapshots must not be null");

        if (snapshots.isEmpty()) {
            return new NormalizedPressureMetrics(
                    0L, 0L, 0.0, 0, totalDurationMs, 0.0, 0.0,
                    fallbackPoolSize, 0, 0.0, 0.0);
        }

        int count = snapshots.size();

        // --- 基础指标 (9 个, 与 NormalizedComparisonMetrics.fromSnapshots() 计算逻辑一致) ---

        // completedTaskCount: 最后一个 snapshot
        PressureSnapshot last = snapshots.get(count - 1).snapshot();
        long completed = last.completedTaskCount();

        // avgQueueDepth + maxQueueDepth
        double avgQueue = 0.0;
        int maxQueue = 0;
        for (ObservedSnapshot s : snapshots) {
            int qs = s.snapshot().queueSize();
            avgQueue += qs;
            if (qs > maxQueue) maxQueue = qs;
        }
        avgQueue /= count;

        // avgActiveThreads
        double avgActive = 0.0;
        for (ObservedSnapshot s : snapshots) {
            avgActive += s.snapshot().activeThreads();
        }
        avgActive /= count;

        // maxPoolSize
        int maxPool = fallbackPoolSize;
        for (ObservedSnapshot s : snapshots) {
            int ps = s.snapshot().poolSize();
            if (ps > maxPool) maxPool = ps;
        }

        double throughput = totalDurationMs > 0
                ? (double) completed / (totalDurationMs / 1000.0)
                : 0.0;

        // --- 派生信号 (2 个) ---

        // queueGrowthRate: 最近 trendWindowSize 个快照的 queueSize 简单线性回归斜率
        double growthRate = 0.0;
        if (trendWindowSize > 0 && count >= 2) {
            int window = Math.min(trendWindowSize, count);
            growthRate = computeQueueGrowthRate(snapshots, count - window, window);
        }

        // threadUtilizationRatio: avgActiveThreads / maxPoolSize
        double utilizationRatio = maxPool > 0 ? avgActive / maxPool : 0.0;

        return new NormalizedPressureMetrics(
                completed, 0L, avgQueue, maxQueue,
                totalDurationMs, throughput, avgActive, maxPool, count,
                growthRate, utilizationRatio);
    }

    /**
     * 简单线性回归: 对 snapshots[offset..offset+window-1] 的 queueSize 计算斜率。
     * 返回每快照的平均 queueSize 变化率。
     */
    private static double computeQueueGrowthRate(
            List<ObservedSnapshot> snapshots, int offset, int window) {
        int n = window;
        double sumX = 0, sumY = 0, sumXY = 0, sumX2 = 0;
        for (int i = 0; i < n; i++) {
            double x = i;
            double y = snapshots.get(offset + i).snapshot().queueSize();
            sumX += x;
            sumY += y;
            sumXY += x * y;
            sumX2 += x * x;
        }
        double denominator = n * sumX2 - sumX * sumX;
        if (denominator == 0) return 0.0;
        return (n * sumXY - sumX * sumY) / denominator;
    }

    // F01 fix: rejectedTaskCount 注入
    public NormalizedPressureMetrics withRejectedTaskCount(long rejected) {
        return new NormalizedPressureMetrics(
                completedTaskCount, rejected, avgQueueDepth, maxQueueDepth,
                totalDurationMs, throughputPerSecond, avgActiveThreads,
                maxPoolSize, snapshotCount, queueGrowthRate, threadUtilizationRatio);
    }
}
```

设计决策：
- F01 fix: `rejectedTaskCount` 在 `fromSnapshots()` 中初始为 0，通过 `withRejectedTaskCount()` 注入真实值（与 `NormalizedComparisonMetrics` 模式一致）
- 前 9 个基础指标的计算逻辑与 `NormalizedComparisonMetrics.fromSnapshots()` 逐行一致（确保两种 metrics 在相同输入下产生相同的基础指标值）
- `queueGrowthRate` 使用最小二乘简单线性回归——对 trendWindowSize 个点的计算复杂度 O(n)，在典型窗口大小（5-10）下开销可忽略
- `threadUtilizationRatio` 在 `maxPool == 0`（空快照）时返回 0.0

### 4.6 SnapshotPressureClassifier

**包**: `com.zhiwu.dynamicthreadpollermanager.experiment.classification`

**职责**: PressureClassifier 的趋势感知实现。无状态——每次 classify() 调用完全自包含。

```java
// 已验证 API 签名:
//   ObservedSnapshot.snapshot() → PressureSnapshot
//   PressureSnapshot.activeThreads() → int, queueSize() → int, poolSize() → int
//   NormalizedPressureMetrics.fromSnapshots(...), withRejectedTaskCount(long)

public final class SnapshotPressureClassifier implements PressureClassifier {

    @Override
    public PressureClassification classify(
            List<ObservedSnapshot> snapshots,
            ClassifierConfig config) {

        Objects.requireNonNull(snapshots, "snapshots must not be null");
        Objects.requireNonNull(config, "config must not be null");

        Instant now = Instant.now();

        // 空快照 → NORMAL, confidence=0.0
        if (snapshots.isEmpty()) {
            NormalizedPressureMetrics emptyMetrics =
                    NormalizedPressureMetrics.fromSnapshots(snapshots, 0L, 0, 0);
            return new PressureClassification(
                    PressureState.NORMAL, 0.0,
                    List.of("No snapshots available — defaulting to NORMAL"),
                    emptyMetrics, now);
        }

        // 计算指标 (totalDurationMs 从 snapshot 时间戳推断)
        int fallbackPoolSize = computeFallbackPoolSize(snapshots);
        long durationMs = computeDurationMs(snapshots);
        NormalizedPressureMetrics metrics =
                NormalizedPressureMetrics.fromSnapshots(
                        snapshots, durationMs, fallbackPoolSize,
                        config.trendWindowSize());

        // 注入 rejectedTaskCount: 从 snapshots 无法获取，保持 fromSnapshots() 的默认值 0
        // 消费方可以在 classify() 前通过 withRejectedTaskCount() 注入

        // --- 按优先级分类 ---

        // 1. REJECTION_ACTIVE: rejectedTaskCount > 0
        if (metrics.rejectedTaskCount() > 0) {
            return build(metrics, PressureState.REJECTION_ACTIVE, 0.95,
                    "rejectedTaskCount=%d > 0".formatted(metrics.rejectedTaskCount()), now);
        }

        double utilization = metrics.threadUtilizationRatio();
        double growth = metrics.queueGrowthRate();
        int maxQueue = metrics.maxQueueDepth();

        // 2. OVERLOAD: utilization >= 0.8 + queue pressure
        boolean queueOverThreshold;
        if (config.queueCapacity() == Integer.MAX_VALUE) {
            queueOverThreshold = maxQueue > 0;
        } else if (config.queueCapacity() == 0) {
            queueOverThreshold = true; // SynchronousQueue — any utilization >= 0.8 is overload
        } else {
            queueOverThreshold = maxQueue >= config.queueCapacity() * 0.5;
        }

        if (utilization >= 0.8 && queueOverThreshold) {
            double conf = utilization >= 0.95 ? 0.95 : 0.85;
            return build(metrics, PressureState.OVERLOAD, conf,
                    "threadUtilization=%.2f, maxQueueDepth=%d, queueCapacity=%d"
                            .formatted(utilization, maxQueue, config.queueCapacity()), now);
        }

        // 3. QUEUE_BUILDUP: queue growing + not yet saturated
        if (growth > config.queueGrowthThreshold() && utilization < 0.8) {
            double conf = Math.min(0.9, 0.6 + growth * 0.3);
            return build(metrics, PressureState.QUEUE_BUILDUP, conf,
                    "queueGrowthRate=%.2f > threshold=%.2f, utilization=%.2f"
                            .formatted(growth, config.queueGrowthThreshold(), utilization), now);
        }

        // 4. RECOVERY: queue declining + utilization falling (F02 fix: 纯趋势特征)
        if (growth < -config.queueGrowthThreshold() && utilization < 0.5 && maxQueue > 0) {
            double conf = Math.min(0.9, 0.6 + Math.abs(growth) * 0.3);
            return build(metrics, PressureState.RECOVERY, conf,
                    "queueGrowthRate=%.2f < -threshold=%.2f, utilization=%.2f, maxQueueDepth=%d"
                            .formatted(growth, config.queueGrowthThreshold(), utilization, maxQueue),
                    now);
        }

        // 5. UNDER_UTILIZED: low utilization + empty queue + no rejections
        if (utilization < 0.3 && maxQueue == 0 && metrics.rejectedTaskCount() == 0) {
            double conf = utilization < 0.1 ? 0.95 : 0.80;
            return build(metrics, PressureState.UNDER_UTILIZED, conf,
                    "threadUtilization=%.2f < 0.3, queue empty, no rejections"
                            .formatted(utilization), now);
        }

        // 6. NORMAL: fallback
        double conf = 0.6 + (1.0 - Math.abs(utilization - 0.5)) * 0.4; // higher conf near utilization=0.5
        return build(metrics, PressureState.NORMAL, conf,
                "Balanced: utilization=%.2f, queueGrowthRate=%.2f, maxQueueDepth=%d"
                        .formatted(utilization, growth, maxQueue), now);
    }

    // --- helpers ---

    private PressureClassification build(
            NormalizedPressureMetrics metrics, PressureState state,
            double confidence, String evidence, Instant now) {
        return new PressureClassification(
                state, clamp(confidence),
                List.of(evidence), metrics, now);
    }

    private static double clamp(double v) {
        return Math.max(0.0, Math.min(1.0, v));
    }

    private static int computeFallbackPoolSize(List<ObservedSnapshot> snapshots) {
        return snapshots.stream()
                .mapToInt(s -> s.snapshot().poolSize())
                .filter(ps -> ps > 0)
                .findFirst()
                .orElse(1);  // never return 0 to avoid division by zero
    }

    private static long computeDurationMs(List<ObservedSnapshot> snapshots) {
        if (snapshots.size() < 2) return 0L;
        Instant first = snapshots.get(0).snapshot().timestamp();
        Instant last = snapshots.get(snapshots.size() - 1).snapshot().timestamp();
        return Duration.between(first, last).toMillis();
    }

    /**
     * 短序列置信度衰减: 当 snapshot 数量不足 trendWindowSize 时，
     * 调用方应在 classify() 后乘以衰减因子。
     * 衰减因子 = min(1.0, snapshotCount / (double) trendWindowSize)
     */
    public static double shortSequenceConfidenceFactor(
            int snapshotCount, int trendWindowSize) {
        if (snapshotCount >= trendWindowSize) return 1.0;
        return (double) snapshotCount / trendWindowSize;
    }
}
```

设计决策：
- **无状态**: 所有分类逻辑基于输入快照序列的内在特征，不依赖跨调用状态。RECOVERY 检测使用纯趋势特征（F02 fix）
- **F03 fix**: OVERLOAD 条件中根据 `queueCapacity` 值（MAX_VALUE/0/正数）选择不同的判断逻辑
- 置信度基于条件匹配程度：明确匹配 → 0.85-0.95，部分匹配 → 0.60-0.80
- `shortSequenceConfidenceFactor()` 作为公开静态方法——调用方负责在快照不足时降低置信度
- `computeFallbackPoolSize()` 从快照中获取第一个非零 poolSize，默认 1（避免除零）

### 4.8 PolicyScorer 接口

**包**: `com.zhiwu.dynamicthreadpollermanager.experiment.classification`

```java
// 已验证 API 签名:

//     scaleUpActiveThreadsThreshold(), scaleUpQueueSizeThreshold(),
//     scaleDownActiveThreadsThreshold()

/**
 * 策略评分器接口。
 *
 * 实现必须保证: compositeScore = responsivenessScore * W_R
 *    + safetyScore * W_S + stabilityScore * W_T + efficiencyScore * W_E
 * 其中 W_R + W_S + W_T + W_E = 1.0。
 */
public interface PolicyScorer {
    PolicyScore score(PressureClassification classification, ThresholdPolicyConfig config);
}
```

### 4.9 ThresholdPolicyScorer

**包**: `com.zhiwu.dynamicthreadpollermanager.experiment.classification`

**职责**: PolicyScorer 的规则式启发实现，4 维度评分。

```java
public final class ThresholdPolicyScorer implements PolicyScorer {

    private final double wResponsiveness;
    private final double wSafety;
    private final double wStability;
    private final double wEfficiency;

    private static final int MAX_SAFE_POOL_SIZE = 128;

    public ThresholdPolicyScorer(
            double wResponsiveness, double wSafety, double wStability, double wEfficiency) {
        double sum = wResponsiveness + wSafety + wStability + wEfficiency;
        if (Math.abs(sum - 1.0) > 0.001) {
            throw new IllegalArgumentException("weights must sum to 1.0, was " + sum);
        }
        this.wResponsiveness = wResponsiveness;
        this.wSafety = wSafety;
        this.wStability = wStability;
        this.wEfficiency = wEfficiency;
    }

    public ThresholdPolicyScorer() {
        this(0.35, 0.30, 0.20, 0.15);  // 默认权重
    }

    @Override
    public PolicyScore score(PressureClassification classification,
                              ThresholdPolicyConfig config) {

        Objects.requireNonNull(classification, "classification must not be null");
        Objects.requireNonNull(config, "config must not be null");

        NormalizedPressureMetrics metrics = classification.metrics();
        PressureState state = classification.state();

        double responsiveness = scoreResponsiveness(state, config, metrics);
        double safety = scoreSafety(config, metrics);
        double stability = scoreStability(config, metrics);
        double efficiency = scoreEfficiency(config, metrics);

        double composite = responsiveness * wResponsiveness
                + safety * wSafety
                + stability * wStability
                + efficiency * wEfficiency;

        String explanation = buildExplanation(state, config.policyId(),
                composite, responsiveness, safety, stability, efficiency);

        return new PolicyScore(
                config.policyId(), composite,
                responsiveness, safety, stability, efficiency,
                explanation);
    }

    // ----- 4 维度评分 -----

    /**
     * Responsiveness: 策略阈值与当前压力水平的匹配度。
     */
    private double scoreResponsiveness(PressureState state,
                                        ThresholdPolicyConfig config,
                                        NormalizedPressureMetrics metrics) {
        return switch (state) {
            case OVERLOAD, QUEUE_BUILDUP -> {
                // 过载/堆积: scale-up 阈值低 → 策略响应快 → 高分
                double tScore = thresholdProximity(
                        metrics.avgActiveThreads(),
                        config.scaleUpActiveThreadsThreshold(), false);
                double qScore = thresholdProximity(
                        metrics.maxQueueDepth(),
                        config.scaleUpQueueSizeThreshold(), false);
                yield (tScore + qScore) / 2.0;
            }
            case UNDER_UTILIZED, RECOVERY -> {
                // 低利用/恢复: scale-down 阈值高 → 策略响应快 → 高分
                double score = thresholdProximity(
                        metrics.avgActiveThreads(),
                        config.scaleDownActiveThreadsThreshold(), true);
                yield score;
            }
            case REJECTION_ACTIVE -> 1.0;  // 拒绝状态下任何策略都需要响应
            case NORMAL -> 0.7;            // 正常状态下中性评分
        };
    }

    /**
     * Safety: 策略参数相对于当前压力状态的合理性（F04 fix: 重定义）。
     */
    private double scoreSafety(ThresholdPolicyConfig config,
                                NormalizedPressureMetrics metrics) {
        double score = 1.0;

        // 容量充足性: maxPoolSize < observed max → 不安全
        if (config.maxPoolSize() < metrics.maxPoolSize()) {
            score -= 0.4;
        }

        // 步长合理性: scaleStep > maxPoolSize * 0.5 → 不安全
        if (config.scaleStep() > config.maxPoolSize() * 0.5) {
            score -= 0.3;
        }

        // 边界合理性: maxPoolSize > 128 或 < 1 → 不安全
        if (config.maxPoolSize() > MAX_SAFE_POOL_SIZE || config.maxPoolSize() < 1) {
            score -= 0.3;
        }

        return clamp(score);
    }

    /**
     * Stability: 策略步长与压力波动性的匹配度。
     */
    private double scoreStability(ThresholdPolicyConfig config,
                                   NormalizedPressureMetrics metrics) {
        double volatility = Math.abs(metrics.queueGrowthRate());
        int step = config.scaleStep();

        // 高波动 + 大步长 → 低分
        if (volatility > 0.5 && step > 4) return 0.2;
        // 高波动 + 小步长 → 中分
        if (volatility > 0.5 && step <= 4) return 0.6;
        // 低波动 + 大步长 → 中分
        if (volatility <= 0.5 && step > 4) return 0.7;
        // 低波动 + 小步长 → 高分
        return 0.9;
    }

    /**
     * Efficiency: 策略避免过度配置的程度（F05 fix: 术语统一）。
     */
    private double scoreEfficiency(ThresholdPolicyConfig config,
                                    NormalizedPressureMetrics metrics) {
        int observedMax = metrics.maxPoolSize();
        int configMax = config.maxPoolSize();

        if (observedMax == 0) return 0.7;  // 无观测数据，中性

        double ratio = (double) configMax / observedMax;

        // config max 接近 observed max → 高效
        if (ratio <= 1.5) return 0.9;
        // 轻微过度配置
        if (ratio <= 3.0) return 0.6;
        // 严重过度配置
        return 0.3;
    }

    // ----- helpers -----

    /**
     * 计算实际值与阈值的接近程度。
     * @param actual 实际观测值
     * @param threshold 策略阈值
     * @param higherIsBetter true: actual 高于 threshold 更接近（scale-down 场景）
     */
    private static double thresholdProximity(
            double actual, double threshold, boolean higherIsBetter) {
        if (threshold == 0) return 0.5;  // 无阈值，中性
        double ratio = actual / threshold;
        if (higherIsBetter) {
            // actual 大于 threshold 时接近 → high score
            return ratio >= 1.0 ? 0.9 : 0.9 * ratio;
        } else {
            // actual 小于 threshold 时接近 → high score（threshold 设得低 = 激进的 scale-up）
            return ratio >= 1.0 ? 0.9 : 0.9 * (1.0 - Math.min(ratio, 1.0));
        }
    }

    private static String buildExplanation(PressureState state, String policyId,
                                            double composite, double r, double s,
                                            double t, double e) {
        return String.format(
                "[%s] Policy '%s': composite=%.2f (R=%.2f, S=%.2f, St=%.2f, E=%.2f)",
                state.name(), policyId, composite, r, s, t, e);
    }

    private static double clamp(double v) {
        return Math.max(0.0, Math.min(1.0, v));
    }
}
```

设计决策：
- F04 fix: Safety 维度不再检查不可能的 minPoolSize=0，改为检查容量充足性/步长合理性/边界合理性
- F05 fix: Efficiency 使用 `metrics.maxPoolSize()`（观测到的最大池大小）而非 "peakPoolSize"
- 权重通过构造器注入，默认为 decision-log D4 的权重
- Responsiveness 根据压力状态采用不同评分策略（OVERLOAD 看重低 scale-up 阈值，UNDER_UTILIZED 看重高 scale-down 阈值）
- 所有 helper 方法是 pure function

### 4.10 PolicyRanker

**包**: `com.zhiwu.dynamicthreadpollermanager.experiment.classification`

```java
public final class PolicyRanker {

    private final PolicyScorer scorer;

    public PolicyRanker(PolicyScorer scorer) {
        this.scorer = Objects.requireNonNull(scorer, "scorer must not be null");
    }

    /**
     * 对多个策略配置评分并按 compositeScore 降序排列。
     */
    public List<PolicyScore> rank(PressureClassification classification,
                                   List<ThresholdPolicyConfig> candidates) {
        Objects.requireNonNull(classification, "classification must not be null");
        Objects.requireNonNull(candidates, "candidates must not be null");

        if (candidates.isEmpty()) {
            return List.of();
        }

        return candidates.stream()
                .map(config -> scorer.score(classification, config))
                .sorted((a, b) -> Double.compare(b.compositeScore(), a.compositeScore()))
                .toList();  // 不可变副本
    }

    /**
     * 返回最高分策略。
     */
    public Optional<PolicyScore> best(PressureClassification classification,
                                       List<ThresholdPolicyConfig> candidates) {
        List<PolicyScore> ranked = rank(classification, candidates);
        return ranked.isEmpty() ? Optional.empty() : Optional.of(ranked.get(0));
    }
}
```

设计决策：
- 排序使用 `Double.compare(b, a)`（降序）
- `toList()` 返回不可变副本
- 稳定排序保证相同分数时保留输入顺序（`Stream.sorted()` 是稳定的当使用 `Comparator` 时，但不保证——使用 `List.sort()` 确保稳定性？其实 `Stream.sorted()` 在顺序流中是稳定的）

### 4.11 SystemCpuProbe

**包**: `com.zhiwu.dynamicthreadpollermanager.experiment.probe`

**职责**: 封装 JDK ManagementFactory 的 CPU 读取。

```java
public final class SystemCpuProbe {

    private final OperatingSystemMXBean osBean;

    public SystemCpuProbe() {
        this.osBean = ManagementFactory.getOperatingSystemMXBean();
    }

    /**
     * 进程级 CPU 使用率 [0.0, 1.0]。
     * 不支持时返回 0.0。
     */
    public double sampleProcessCpuLoad() {
        if (osBean instanceof com.sun.management.OperatingSystemMXBean sunBean) {
            double load = sunBean.getProcessCpuLoad();
            return load >= 0 ? load : 0.0;
        }
        return 0.0;
    }

    /**
     * 系统级 CPU 负载均值（Unix-like）。
     * 不支持时返回 0.0。
     */
    public double sampleSystemCpuLoad() {
        double load = osBean.getSystemLoadAverage();
        return load >= 0 ? load : 0.0;
    }
}
```

设计决策：
- 零外部依赖——仅使用 `java.lang.management` 和 `com.sun.management`（JDK 内置）
- 不缓存值（每次调用读取最新值）——`getProcessCpuLoad()` 本身就有内部平滑
- `getProcessCpuLoad()` 首次调用返回 -1（未初始化）→ 映射为 0.0
- 非 Sun JDK 上 `sampleProcessCpuLoad()` 返回 0.0（graceful degradation）

### 4.12 RuntimeObservation.fromExecutor() 修改

**包**: `com.zhiwu.dynamicthreadpollermanager.experiment.metrics`

**变更**: F06 fix——添加重载方法支持 CPU probe 注入。

```java
// 已验证 API 签名:
//   现有: fromExecutor(ManagedExecutor executor, Instant timestamp)
//   调用链: ManagedExecutor.getActiveCount() → int, getPoolSize() → int,
//           getQueueSize() → int, getCompletedTaskCount() → long
//   MetricValue.present(T) → MetricValue<T>, MetricValue.absent() → MetricValue<T>

/**
 * CPU probe 可注入的重载（F06 fix）。
 * 原方法委托到此方法，传入 new SystemCpuProbe()。
 */
public static RuntimeObservation fromExecutor(
        ManagedExecutor executor, Instant timestamp, SystemCpuProbe cpuProbe) {

    MetricValue<Double> cpu = MetricValue.absent();
    if (cpuProbe != null) {
        double cpuLoad = cpuProbe.sampleProcessCpuLoad();
        if (cpuLoad >= 0) {
            cpu = MetricValue.present(cpuLoad);
        }
    }

    return new RuntimeObservation(
            timestamp,
            MetricValue.present(executor.getActiveCount()),
            MetricValue.present(executor.getPoolSize()),
            MetricValue.present(executor.getQueueSize()),
            MetricValue.present(executor.getCompletedTaskCount()),
            cpu,
            MetricValue.present(executor.getKeepAliveTime(TimeUnit.SECONDS)),
            MetricValue.present(executor.getLargestPoolSize()),
            MetricValue.present(executor.getTaskCount()));
}

/**
 * 原方法签名不变——委托到重载方法，默认使用真实 CPU probe。
 */
public static RuntimeObservation fromExecutor(
        ManagedExecutor executor, Instant timestamp) {
    return fromExecutor(executor, timestamp, new SystemCpuProbe());
}
```

设计决策：
- 原两个参数的 `fromExecutor()` 方法签名不变
- 内部委托到三个参数的重载，传入 `new SystemCpuProbe()`
- `cpuProbe` 为 null 或 CPU 读取失败时 `cpuUtilization` 保持 `MetricValue.absent()`
- `DefaultSnapshotAssembler` 无需修改——已正确处理 absent → 0.0 映射
