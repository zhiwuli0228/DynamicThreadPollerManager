## 1. 设计目标

v0.16.0 SR 将已闭环 IR 转成 capability 的功能设计。目标：在 v0.15.0 的多执行器协调和闭环交叉验证基础上，实现 6 个能力范围 — 复杂工作负载场景、回滚感知调整、基于时间的冷却、反振荡门、复杂场景验证报告、v0.15 遗留风险修复。

关键架构约束：新类型与已有接口组合（`ExecutorAdjustmentAdapter`、`RuntimeAdjustmentSafetyGate`）。无接口方法新增。`AdjustmentLoop` 公开 API 不变。`ScenarioProfile` 枚举安全扩展（仅在 planner switch 中使用，无多态分发）。

## 2. 设计结论

- **ScenarioProfile 扩展**: `LONG_TAIL`、`MIXED_CPU_IO`、`DOWNSTREAM_BLOCKED` 三个新枚举值
- **DeterministicScenarioPlanner**: 扩展 `plan()` 方法，三种新 profile 各有确定性公式，使用 `ScenarioDefinition.seed()`
- **RollbackAwareAdjustmentAdapter**: `experiment.adjustment` 包中的装饰器。捕获调整前/后快照，检测队列深度退化，通过安全门发出有界（1x）回滚。回滚动作通过 `BiConsumer` 回调报告
- **TimeBasedCooldownSafetyGate**: 实现 `RuntimeAdjustmentSafetyGate`。`Supplier<Instant>` 时钟注入。冷却窗口检查。紧急回滚绕过。保留所有其他安全检查
- **AntiOscillationGuard**: `experiment.loop` 包中的独立守卫。咨询 `OscillationDetector`，计数连续振荡，超过可配置 `blockThreshold` 后激活。紧急回滚绕过。稳定成功后重置
- **ComplexScenarioReport + Generator**: 不可变 record + 从 `EvidenceRecorder`/`LoopEvidenceRecorder`/`AdjustmentHistory` 读取的生成器。从真实数据计算所有指标
- **v0.15 风险修复**: computeSignificance() 真实快照数组、GroupLoopOrchestrator null 修复、线程安全 Javadoc、并发 + 行为测试
- 现有测试零回归

### 4.2 R2: 回滚感知调整适配器

**RollbackAwareAdjustmentAdapter** — `experiment.adjustment` 包中的装饰器。

```java
public final class RollbackAwareAdjustmentAdapter implements ExecutorAdjustmentAdapter {
    // 构造器
    public RollbackAwareAdjustmentAdapter(
            ExecutorAdjustmentAdapter delegate,          // 非 null
            RuntimeAdjustmentSafetyGate safetyGate,       // 非 null，用于回滚命令
            DegradationConfig degradationConfig,          // 非 null，配置阈值
            BiConsumer<AdjustmentResult, AdjustmentResult> rollbackListener, // nullable
            Supplier<Instant> clock)                      // 非 null，回滚命令时间戳

    // apply() 逻辑：
    // 1. currentState() → preSnapshot
    // 2. delegate.apply(command) → delegateResult
    // 3. if status != APPLIED → return delegateResult
    // 4. currentState() → postSnapshot
    // 5. if !isDegraded(preSnapshot, postSnapshot) → return delegateResult
    // 6. executeRollback(...)
}
```

**退化检测** (`isDegraded`):
- 比较前后队列深度
- `postQueue - preQueue > degradationConfig.queueDepthThreshold()` → 已退化
- 注意: `DegradationConfig` 包含三个阈值，当前仅使用 `queueDepthThreshold`（IR review F04，已记录为已知限制）

**回滚执行** (`executeRollback`):
- 使用 `emergencyRollback = true` 构造 `ScaleAdjustmentCommand`
- Target = `preSnapshot.corePoolSize()`
- 通过 `safetyGate.evaluate(rollbackCommand, ...)` 传递
- 如果 gate REJECTED → 通过监听器报告（原始结果，null 回滚），返回原始 result
- 如果 gate ALLOW → `safetyGate.recordApplied()`，然后 `delegate.apply(rollbackCommand)`
- 通过监听器报告（原始结果，回滚结果）
- 返回回滚 result

**有界**: 无显式 `rollingBack` 标志 — `executeRollback()` 不调用自身。单层递归通过设计防止：`executeRollback` → `delegate.apply()` 不触发另一个 `executeRollback`（在初始 `apply()` 调用之外）。

**证据**: BiConsumer 回调 `(originalResult, rollbackResult)` 或 `(originalResult, null)`（如果 gate 拒绝）。调用者（`AdjustmentLoop`）负责将此转发到 `LoopEvidenceRecorder`。

**API 签名验证**:
- `ExecutorAdjustmentAdapter.currentState()`: `ExecutorStateSnapshot` — 已验证
- `ExecutorAdjustmentAdapter.apply(ScaleAdjustmentCommand)`: `AdjustmentResult` — 已验证
- `RuntimeAdjustmentSafetyGate.evaluate(ScaleAdjustmentCommand, ExecutorStateSnapshot, ReadinessAssessment)`: `SafetyGateDecision` — 已验证
- `SafetyGateDecision.Outcome.REJECTED` — 已验证
- `SafetyGateDecision.Outcome.ALLOW` — 已验证
- `ScaleAdjustmentCommand.create(runId, instant, currentPoolSize, targetPoolSize, reason, sourceDecisionRef, clock, boolean)` — 已验证（新增 `emergency` 参数重载）
- `ReadinessAssessment` 构造器: `(ReadinessStatus, List<String>, List<String>, List<String>, List<String>, String, List<String>)` — 已验证

### 4.3 R3: 基于时间的冷却安全门

**TimeBasedCooldownSafetyGate** — 实现 `RuntimeAdjustmentSafetyGate`。

```java
public final class TimeBasedCooldownSafetyGate implements RuntimeAdjustmentSafetyGate {
    public TimeBasedCooldownSafetyGate(
            SafetyGateConfig config,
            Duration cooldownDuration,       // 非 null，非负
            Supplier<Instant> clock)         // 非 null

    // evaluate() — synchronized:
    // 1. 验证：(targetPoolSize >= 1, currentPoolSize >= 0)
    // 2. 就绪检查：NOT_READY → REJECTED
    // 3. 就绪伴随风险检查：READY_WITH_RISK && !config.allowReadyWithRisk() → REJECTED
    // 4. 冷却窗口（非紧急）：lastAppliedInstant.get(runId) → Duration < cooldown → REJECTED
    // 5. 每运行限制检查：appliedAdjustmentsForRun >= maxAdjustmentsPerRun → REJECTED
    // 6. 相反方向检查（非紧急）：direction != lastDirection && target == current → REJECTED
    // 7. 无操作检查：noOp || target == currentSize → NO_OP
    // 8. 其他：ALLOW
}
```

**注意 — IR review F01/F03**: `lastAppliedInstant` key 为 `command.runId()`（非 executor name）。在多执行器组场景中，这可能导致执行器间冷却共享。记录为已知 P1 偏差 — SR review 将处理。

**生命周期**: 实例绑定到单次运行。运行完成后丢弃并由 GC 回收 `lastAppliedInstant` map。

**保留的安全检查** (对照 `DefaultRuntimeAdjustmentSafetyGate` 源码验证):
1. 命令验证（targetPoolSize >= 1, currentPoolSize >= 0）
2. NOT_READY 状态拒绝
3. READY_WITH_RISK 伴随风险拒绝（如果 config 不允许）
4. 冷却窗口拒绝（已从计数器替换为基于时间）
5. 每运行限制 (RUN_LIMIT_EXCEEDED)
6. 相反方向拒绝（如果 config blockImmediateOppositeDirection）
7. 无操作检测（no-op 标志或 target == current）
8. ALLOW

**API 签名验证**:
- `SafetyGateConfig` 字段: `maxAdjustmentsPerRun()`, `allowReadyWithRisk()`, `blockImmediateOppositeDirection()` — 已验证
- `SafetyGateDecision.allow(int, ScaleAdjustmentCommand)` — 已验证
- `SafetyGateDecision.rejected(AdjustmentFailureCode, String)` — 已验证
- `SafetyGateDecision.noOp(String)` — 已验证

### 4.4 R4: 反振荡守卫

**AntiOscillationGuard** — `experiment.loop` 包中的独立类。

```java
public final class AntiOscillationGuard {
    public AntiOscillationGuard(
            OscillationDetector detector,   // 非 null
            int blockThreshold)             // >= 1

    // synchronized evaluate():
    // 1. 如果 pending.isNoOp() → NO_OP
    // 2. 如果 isEmergencyRollback → NO_OP（绕过，不携带 command）
    // 3. wouldOscillate = detector.wouldOscillate(pending, history)
    // 4. 如果是 → 递增计数器；否则 → counter=0, activated=false
    // 5. 如果 counter >= threshold → 激活，REJECTED w/ ANTI_OSCILLATION_ACTIVE
    // 6. 否则 → NO_OP（无阻断，不携带 command）
}
```

**`AdjustmentLoop` 集成** — 第 7.5 步（振荡检查与冷却门之间）:

```java
// 步骤 7.5: 反振荡守卫
if (antiOscillationGuard != null) {
    SafetyGateDecision guardDecision = antiOscillationGuard.evaluate(
            decision, history, command.isEmergencyRollback());
    if (!guardDecision.isAllowed()) {
        loopEvidenceRecorder.recordIteration(...);
        return; // 阻断此迭代
    }
}
```

守卫作为可空构造器参数注入。已区分 `AntiOscillationGuard`（nullable）与 `oscillationDetector`、`calibrator`（non-null）。

**API 签名验证**:
- `OscillationDetector.wouldOscillate(AdjustmentDecision, AdjustmentHistory)`: `boolean` — 已验证
- `AdjustmentDecision.isNoOp()`: `boolean` — 假定存在于接口

## 6. 失败语义

| 失败 | 代码 | 行为 |
|------|------|------|
| 冷却激活 | `COOLDOWN_ACTIVE` | 拒绝非紧急；允许紧急回滚 |
| 反振荡激活 | `ANTI_OSCILLATION_ACTIVE` | 拒绝非紧急；允许紧急回滚 |
| 检测到回滚退化 | N/A | 通过安全门发出回滚；如果回滚也退化，返回回滚结果（无递归） |
| 安全门拒绝回滚 | 门的失败码 | 记录拒绝；返回原始（未回滚）AdjustmentResult |
| RollbackAwareAdapter 中 null delegate | `NullPointerException` | 在构造时快速失败 |
| TimeBasedCooldownGate 中 null clock | `NullPointerException` | 在构造时快速失败 |
| GroupLoopOrchestrator 中 null ExecutorRegistry | `IllegalArgumentException` | 在 startAll() 中快速失败（通过 AtomicDeletionSafety 防止） |
| 未达到退化阈值 | N/A | 返回原始 AdjustmentResult；无回滚 |

## 7. 并发与资源所有权

- `TimeBasedCooldownSafetyGate`: `synchronized evaluate()` 和 `recordApplied()`。仅在 synchronized 方法内访问 `lastAppliedInstant` map
- `AntiOscillationGuard`: `synchronized evaluate()` 和 `reset()`
- `RollbackAwareAdjustmentAdapter`: 每次调用无状态。`apply()` 方法在单次调用内完成所有操作 — 跨调用无共享可变状态
- `InMemoryEvidenceRecorder`: 已线程安全（`ConcurrentHashMap` + `CopyOnWriteArrayList`）。线程安全契约已记录在 Javadoc 中
- `FileBackedEvidenceRecorder`: 已线程安全（`ConcurrentHashMap` 缓冲 + `Files.writeString` with APPEND）
- `AdjustmentLoop` 集成: 守卫和门在循环守护线程内评估。循环在守卫/门评估期间不持有锁 — 这是安全的，因为守卫和门在内部是 synchronized 的

## 9. 已知偏差与残余风险

| 偏差 | 级别 | 细节 | 修复方案 | 触发条件 |
