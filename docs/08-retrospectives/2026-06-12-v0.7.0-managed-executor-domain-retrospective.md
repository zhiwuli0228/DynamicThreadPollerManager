## 发生的问题

### P1: 测试未考虑 ThreadPoolExecutor 实际验证规则

`setCorePoolSizeShouldReflectImmediately` 测试将 core=2 的 executor 直接 `setCorePoolSize(8)`，但 `ThreadPoolExecutor.setCorePoolSize()` 要求 `corePoolSize <= maximumPoolSize`，导致 `IllegalArgumentException`。

**根因**: 测试先于对真实 TPE API 的理解写出。ManagedExecutor 是 TPE 的薄包装，TPE 的验证规则直接透传。

**修复**: 测试改为先 `setMaximumPoolSize(8)` 再 `setCorePoolSize(3)`。

### P2: 硬编码枚举数量导致级联测试失败

`AdjustmentContractsTest` 硬编码 `assertEquals(8, AdjustmentFailureCode.values().length)`，新增 `EXECUTOR_NOT_FOUND` 后需同步更新。

**根因**: 测试对枚举基数做了精确断言，而非只检查必需常量存在性。

**修复**: 更新计数为 9，同时添加 `EXECUTOR_NOT_FOUND` 断言。

### P3: TPE 异常路径无法通过公共 API 到达

`applyShouldReturnFailedWhenThreadPoolExecutorRejects` 试图验证 TPE 抛出异常时的 FAILED 路径，但：
- 安全门先于 TPE 捕获 `targetPoolSize < 1`
- `ScaleAdjustmentCommand.create()` 验证 `targetPoolSize >= 0`
- 适配器在设置核心数前先提升 maximum

三条防线使 TPE 的 `IllegalArgumentException` 在公共 API 路径上不可达。

**根因**: 过度防御设计使异常路径成为死代码。

**处置**: 替换为 permissive safety gate 的边界值测试；TPE 异常捕获作为安全网保留（不删除）。

### P4: outputs/ 目录未 gitignore 导致 post-archive guard 失败

首次 post-archive guard 因 `outputs/` 目录未跟踪而报告 worktree dirty。

**根因**: 历史遗留的本地输出目录未纳入 `.gitignore`。

**修复**: 添加 `outputs/` 到 `.gitignore`。

### P5: 空状态快照构造值无效

`ManagedExecutorAdjustmentAdapter` 在 executor 未找到时构造快照使用 `corePoolSize=0, maximumPoolSize=0`，但 `ExecutorStateSnapshot.Builder` 要求 `corePoolSize > 0`。

**根因**: 未在编码前检查 Builder 的验证规则。

**修复**: 改为 `corePoolSize=1, maximumPoolSize=1`。

### P6: 清理测试时序竞争

`deletionSafetyAndRegistryCleanupAfterExperiment` 在 `CountDownLatch` 释放前调用 `awaitTermination()`，导致超时而非正常终止。

**根因**: shutdown → awaitTermination → release latch 顺序错误；任务仍阻塞在 latch 上时调用 awaitTermination。

**修复**: 先 `countDown()` 释放任务，再 `shutdown()` + `awaitTermination()`。

## 流程改进

### 需要固化到规则的改进

1. **测试驱动顺序**: 在编写测试断言前，先确认被测 API（尤其是包装的真实实现，如 TPE）的实际验证规则。→ 建议在 `docs/04-development/testing-guide.md` 补充"包装真实实现的测试必须先验证底层 API 行为"规则。

2. **枚举计数测试**: 避免对枚举 `values().length` 做精确断言；改为检查必需的常量存在性。→ 建议在 testing-guide 中补充"枚举测试应检查语义存在性，不检查基数"。

3. **worktree 清洁度**: 本地输出目录必须纳入 `.gitignore`，避免 post-archive guard 因 untracked 文件失败。→ `outputs/` 已添加；未来新目录应在创建时同步处理。

4. **SR 伪代码一致性**: SR 中的 API 草稿应在进入 OpenSpec 阶段前与实际代码对齐。→ `ScaleAdjustmentCommand` 只有一个 `targetPoolSize()`，SR 不应写出 `targetCorePoolSize()`/`targetMaxPoolSize()`。

### 后续 agent 必须遵守的行为

- 每完成一个独立源码修改后立即运行 `mvn test`（或 `mvn compile`），而非等所有修改完成。
- 在 `@AfterEach` 中释放所有 CountDownLatch 后再调用 shutdown/awaitTermination。
- 使用 `ExecutorStateSnapshot.builder()` 时，`corePoolSize` 必须 >= 1。
- 新增枚举常量时必须同步检查并更新 `AdjustmentContractsTest` 中的计数和存在性断言。
